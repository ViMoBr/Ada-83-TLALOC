PATCH codi_x86_64U.finc  --  palier 5 : fichiers, premiere moitie
CREATE / WRITE / CLOSE. OPEN, READ, SET_POS, GET_POS, GET_SIZE et DELETE restent
neutralises et rendent -1.

Verifie sous OVMF sur une image FAT reelle : creation, ecriture de 59 octets,
fermeture, puis relecture du fichier depuis l'hote par mtype. Puis reecriture du
meme fichier avec 7 octets pour verifier la troncature.

Six retouches.
  1. constantes : offsets des trois protocoles et modes d'ouverture
  2. .data : les deux GUID, en tete de section
  3. .bss  : pointeurs de protocoles, tampon de nom, taille d'entree-sortie
  4. le bloc UEFI_FS_ROOT + UEFI_NAME_UTF16, insere avant SYS_FILE_CREATE
  5. SYS_FILE_CREATE
  6. SYS_FILE_WRITE et SYS_FILE_CLOSE

PATCH 1  --  constantes

--- BLOC A INSERER -----------------------------------------------------------------------------------

LIP_DeviceHandle	= 0x18				; dans EFI_LOADED_IMAGE_PROTOCOL
SFS_OpenVolume		= 0x08				; dans EFI_SIMPLE_FILE_SYSTEM_PROTOCOL
FILE_Open		= 0x08				; dans EFI_FILE_PROTOCOL
FILE_Close		= 0x10				;   idem
FILE_Delete		= 0x18				;   idem
FILE_Read		= 0x20				;   idem
FILE_Write		= 0x28				;   idem
FILE_GetPosition	= 0x30				;   idem
FILE_SetPosition	= 0x38				;   idem
EFI_FILE_MODE_RW	= 3				; READ(1) | WRITE(2)
EFI_FILE_MODE_CRW	= 0x8000000000000003		; CREATE | READ | WRITE
EFI_FILE_ARCHIVE	= 0x20				; attribut, seulement a la creation
UEFI_NAME_MAX		= 255				; CHAR16 utiles dans un nom de fichier

PATCH 2  --  .data : les deux GUID
========================================================================================================
--- ANCRE (ne pas modifier, sert a se reperer) --------------------------------------------------------
section '.data' data readable writeable
(inserer JUSTE APRES l'ancre, donc en tete de section)
--- BLOC A INSERER -----------------------------------------------------------------------------------

;	Les protocoles UEFI ne se nomment pas : ils s'identifient par un GUID de
;	16 octets, dont les trois premiers champs sont en petit-boutien et les
;	huit derniers octets en ordre naturel. Places en tete de section, donc
;	alignes sur 16 : certains firmwares comparent les GUID par mots de 32 bits.
GUID_LOADED_IMAGE:	dd 0x5B1B31A1
			dw 0x9562, 0x11D2
			db 0x8E, 0x3F, 0x00, 0xA0, 0xC9, 0x69, 0x72, 0x3B
GUID_SIMPLE_FS:		dd 0x964E5B22
			dw 0x6459, 0x11D2
			db 0x8E, 0x39, 0x00, 0xA0, 0xC9, 0x69, 0x72, 0x3B

PATCH 3  --  .bss
========================================================================================================
--- ANCRE (ne pas modifier, sert a se reperer) --------------------------------------------------------
UEFI_EPOCH_ANCHOR:	rq 1					; secondes Unix au moment de l'ancrage
--- BLOC A INSERER -----------------------------------------------------------------------------------
UEFI_LIP:		rq 1					; EFI_LOADED_IMAGE_PROTOCOL* de notre propre image
UEFI_SFS:		rq 1					; EFI_SIMPLE_FILE_SYSTEM_PROTOCOL* du volume d'amorcage
UEFI_FS_ROOT_PTR:	rq 1					; EFI_FILE_PROTOCOL* du repertoire racine (0 = pas encore ouvert)
UEFI_FILE_TMP:		rq 1					; handle rendu par Open
UEFI_IO_SIZE:		rq 1					; UINTN d'entree-sortie de Read et Write
UEFI_NAME_BUF:		rw UEFI_NAME_MAX + 1			; nom de fichier converti en UTF-16

PATCH 4  --  la chaine de protocoles et la conversion du nom
========================================================================================================
--- ANCRE (ne pas modifier, sert a se reperer) --------------------------------------------------------
;			---------------
macro			SYS_FILE_CREATE
(inserer le bloc ci-dessous JUSTE AVANT l'ancre)
--- BLOC A INSERER -----------------------------------------------------------------------------------
;-----------------------------------------------------------------------------------------------------------------------
;			F I C H I E R S   U E F I
;-----------------------------------------------------------------------------------------------------------------------
;	Il n'y a pas d'espace de noms global sous UEFI : pas de repertoire courant,
;	pas de chemin absolu. On atteint un fichier par une CHAINE DE PROTOCOLES,
;	chacun obtenu du precedent :
;
;	  ImageHandle --HandleProtocol(LOADED_IMAGE)--> LoadedImage
;	              --champ DeviceHandle-----------> le volume d'ou on a demarre
;	              --HandleProtocol(SIMPLE_FS)----> SimpleFileSystem
;	              --OpenVolume()-----------------> racine, un EFI_FILE_PROTOCOL
;	              --Open( nom )------------------> le fichier, meme protocole
;
;	Les fichiers sont donc relatifs au volume d'amorcage, et a lui seul. Un
;	programme TLALOC lit et ecrit sur la cle qui l'a charge. Les separateurs
;	sont des contre-obliques et les noms sont en UTF-16.
;
;	Le handle rendu a Ada est le pointeur EFI_FILE_PROTOCOL lui-meme, ce qui
;	conserve le contrat des trois autres cibles : une valeur opaque, ou -1.
;
;	La chaine de protocoles n'est parcourue qu'une fois, a la premiere
;	ouverture, et le resultat garde dans UEFI_FS_ROOT_PTR : rien n'est paye
;	par un programme qui ne touche aucun fichier.

;			-------------
macro			UEFI_FS_ROOT					; -> RAX = racine du volume d'amorcage, 0 si echec
;			-------------
  local r_fail, r_done
  db 0x48, 0x8B, 0x05						; mov rax,[rip+UEFI_FS_ROOT_PTR]
  dd UEFI_FS_ROOT_PTR - ($ + 4)
  db 0x48, 0x85, 0xC0						; test rax,rax
  db 0x0F, 0x85							; jnz r_done		deja ouverte
  dd r_done - ($ + 4)

			; 1. HandleProtocol( ImageHandle, &GUID_LOADED_IMAGE, &UEFI_LIP )
  db 0x4C, 0x8B, 0x15						; mov r10,[rip+UEFI_SYSTEM_TABLE]
  dd UEFI_SYSTEM_TABLE - ($ + 4)
  db 0x4D, 0x8B, 0x52, BootServices				; mov r10,[r10+0x60]
  db 0x4D, 0x8B, 0x92						; mov r10,[r10+0x98]	R10 = &HandleProtocol
  dd HandleProtocol
  db 0x48, 0x8B, 0x0D						; mov rcx,[rip+UEFI_IMAGE_HANDLE]
  dd UEFI_IMAGE_HANDLE - ($ + 4)
  db 0x48, 0x8D, 0x15						; lea rdx,[rip+GUID_LOADED_IMAGE]
  dd GUID_LOADED_IMAGE - ($ + 4)
  db 0x4C, 0x8D, 0x05						; lea r8,[rip+UEFI_LIP]
  dd UEFI_LIP - ($ + 4)
  db 0x48, 0x89, 0xE0						; mov rax,rsp
  db 0x48, 0x83, 0xE4, 0xF0						; and rsp,-16
  db 0x48, 0x83, 0xEC, 0x30						; sub rsp,48
  db 0x48, 0x89, 0x44, 0x24, 0x28					; mov [rsp+40],rax
  db 0x41, 0xFF, 0xD2						; call r10
  db 0x48, 0x8B, 0x64, 0x24, 0x28					; mov rsp,[rsp+40]
  db 0x48, 0x85, 0xC0						; test rax,rax		EFI_SUCCESS ?
  db 0x0F, 0x85							; jnz r_fail
  dd r_fail - ($ + 4)

			; 2. HandleProtocol( LoadedImage->DeviceHandle, &GUID_SIMPLE_FS, &UEFI_SFS )
  db 0x4C, 0x8B, 0x15						; mov r10,[rip+UEFI_SYSTEM_TABLE]
  dd UEFI_SYSTEM_TABLE - ($ + 4)
  db 0x4D, 0x8B, 0x52, BootServices				; mov r10,[r10+0x60]
  db 0x4D, 0x8B, 0x92						; mov r10,[r10+0x98]
  dd HandleProtocol
  db 0x48, 0x8B, 0x0D						; mov rcx,[rip+UEFI_LIP]
  dd UEFI_LIP - ($ + 4)
  db 0x48, 0x8B, 0x49, LIP_DeviceHandle				; mov rcx,[rcx+0x18]	le volume d'amorcage
  db 0x48, 0x8D, 0x15						; lea rdx,[rip+GUID_SIMPLE_FS]
  dd GUID_SIMPLE_FS - ($ + 4)
  db 0x4C, 0x8D, 0x05						; lea r8,[rip+UEFI_SFS]
  dd UEFI_SFS - ($ + 4)
  db 0x48, 0x89, 0xE0						; mov rax,rsp
  db 0x48, 0x83, 0xE4, 0xF0						; and rsp,-16
  db 0x48, 0x83, 0xEC, 0x30						; sub rsp,48
  db 0x48, 0x89, 0x44, 0x24, 0x28					; mov [rsp+40],rax
  db 0x41, 0xFF, 0xD2						; call r10
  db 0x48, 0x8B, 0x64, 0x24, 0x28					; mov rsp,[rsp+40]
  db 0x48, 0x85, 0xC0						; test rax,rax
  db 0x0F, 0x85							; jnz r_fail
  dd r_fail - ($ + 4)

			; 3. SimpleFileSystem->OpenVolume( SimpleFileSystem, &UEFI_FS_ROOT_PTR )
  db 0x48, 0x8B, 0x0D						; mov rcx,[rip+UEFI_SFS]
  dd UEFI_SFS - ($ + 4)
  db 0x4C, 0x8B, 0x51, SFS_OpenVolume				; mov r10,[rcx+0x08]
  db 0x48, 0x8D, 0x15						; lea rdx,[rip+UEFI_FS_ROOT_PTR]
  dd UEFI_FS_ROOT_PTR - ($ + 4)
  db 0x48, 0x89, 0xE0						; mov rax,rsp
  db 0x48, 0x83, 0xE4, 0xF0						; and rsp,-16
  db 0x48, 0x83, 0xEC, 0x30						; sub rsp,48
  db 0x48, 0x89, 0x44, 0x24, 0x28					; mov [rsp+40],rax
  db 0x41, 0xFF, 0xD2						; call r10
  db 0x48, 0x8B, 0x64, 0x24, 0x28					; mov rsp,[rsp+40]
  db 0x48, 0x85, 0xC0						; test rax,rax
  db 0x0F, 0x85							; jnz r_fail
  dd r_fail - ($ + 4)
  db 0x48, 0x8B, 0x05						; mov rax,[rip+UEFI_FS_ROOT_PTR]
  dd UEFI_FS_ROOT_PTR - ($ + 4)
  db 0xE9							; jmp r_done
  dd r_done - ($ + 4)
r_fail:
  db 0x31, 0xC0							; xor eax,eax
  db 0x48, 0x89, 0x05						; mov [rip+UEFI_FS_ROOT_PTR],rax
  dd UEFI_FS_ROOT_PTR - ($ + 4)
r_done:
end macro

;			---------------
macro			UEFI_NAME_UTF16					; RSI = @descripteur Ada -> UEFI_NAME_BUF
;			---------------
;	Meme travail que COPY_STRING_APPEND_NUL, mais en CHAR16 et avec traduction
;	des obliques en contre-obliques : UEFI ne connait que la contre-oblique.
  local n_loop, n_store, n_fit, n_done
  db 0x48, 0x8B, 0x46, 0x08						; mov rax,[rsi+8] : @USEINFO
  db 0x8B, 0x48, 0x0C						; mov ecx,[rax+12] : last
  db 0xFF, 0xC1							; inc ecx
  db 0x2B, 0x48, 0x08						; sub ecx,[rax+8] : longueur
  db 0x48, 0x8B, 0x36						; mov rsi,[rsi] : @DATA
  db 0x48, 0x8D, 0x3D						; lea rdi,[rip+UEFI_NAME_BUF]
  dd UEFI_NAME_BUF - ($ + 4)
  db 0x81, 0xF9							; cmp ecx,UEFI_NAME_MAX
  dd UEFI_NAME_MAX
  db 0x76, n_fit - ($ + 1)						; jbe n_fit
  db 0xB9							; mov ecx,UEFI_NAME_MAX	nom tronque
  dd UEFI_NAME_MAX
n_fit:
  db 0x85, 0xC9							; test ecx,ecx
  db 0x74, n_done - ($ + 1)						; jz n_done		nom vide
n_loop:
  db 0x0F, 0xB6, 0x06						; movzx eax,byte [rsi]
  db 0x48, 0xFF, 0xC6						; inc rsi
  db 0x83, 0xF8, 0x2F						; cmp eax,'/'
  db 0x75, n_store - ($ + 1)						; jne n_store
  db 0xB8, 0x5C, 0x00, 0x00, 0x00					; mov eax,'\\'	UEFI separe par contre-oblique
n_store:
  db 0x66, 0x89, 0x07						; mov [rdi],ax
  db 0x48, 0x83, 0xC7, 0x02						; add rdi,2
  db 0xFF, 0xC9							; dec ecx
  db 0x75, n_loop - ($ + 1)						; jnz n_loop
n_done:
  db 0x66, 0xC7, 0x07, 0x00, 0x00					; mov word [rdi],0	terminateur CHAR16
end macro

PATCH 5  --  SYS_FILE_CREATE
========================================================================================================
--- BLOC A SUPPRIMER ---------------------------------------------------------------------------------
;			---------------
macro			SYS_FILE_CREATE				; CreateFileA(..., CREATE_ALWAYS, ...) -> HANDLE ou -1
;			---------------
  POP_RSI								; @descripteur du nom Ada
  COPY_STRING_APPEND_NUL						; RDI = nom C termine par NUL

  ; CreateFileA( name, GENERIC_READ|GENERIC_WRITE,
  ;              FILE_SHARE_READ|FILE_SHARE_WRITE|FILE_SHARE_DELETE,
  ;              NULL, CREATE_ALWAYS, FILE_ATTRIBUTE_NORMAL, NULL )
  ; Cadre Win64 : shadow 32, args 5..7 aux offsets 32/40/48, ancien RSP a 56.
  db 0x48, 0x89, 0xE0						; mov rax,rsp
  db 0x48, 0x83, 0xE4, 0xF0						; and rsp,-16
  db 0x48, 0x83, 0xEC, 0x40						; sub rsp,64
  db 0x48, 0x89, 0x44, 0x24, 0x38					; mov [rsp+56],rax
  db 0xC7, 0x44, 0x24, 0x20, 2, 0, 0, 0					; [rsp+32] = CREATE_ALWAYS (2)
  db 0xC7, 0x44, 0x24, 0x28, 0x80, 0, 0, 0				; [rsp+40] = FILE_ATTRIBUTE_NORMAL (80h)
  db 0x48, 0xC7, 0x44, 0x24, 0x30, 0, 0, 0, 0				; [rsp+48] = hTemplateFile = NULL
  db 0x48, 0x89, 0xF9						; mov rcx,rdi : lpFileName
  db 0xBA, 0, 0, 0, 0xC0						; mov edx,C0000000h : GENERIC_READ|GENERIC_WRITE
  db 0x41, 0xB8, 7, 0, 0, 0						; mov r8d,7 : SHARE_READ|WRITE|DELETE
  db 0x45, 0x31, 0xC9						; xor r9d,r9d : lpSecurityAttributes=NULL
  db 0x48, 0xC7, 0xC0, 0xFF, 0xFF, 0xFF, 0xFF			; mov rax,-1 : service non porte sur UEFI
  db 0x48, 0x8B, 0x64, 0x24, 0x38					; mov rsp,[rsp+56]
  db 0x48, 0x89, 0x45, 0x00						; mov [rbp],rax : HANDLE ou INVALID_HANDLE_VALUE=-1
end macro
--- BLOC A INSERER -----------------------------------------------------------------------------------
;			---------------
macro			SYS_FILE_CREATE				; Open(CREATE) -> EFI_FILE_PROTOCOL* ou -1
;			---------------
;	CREATE_ALWAYS de Windows TRONQUE un fichier existant ; Open(CREATE) d'UEFI,
;	non : il rend le fichier tel quel, avec son ancien contenu au-dela de ce
;	qu'on ecrira. On reproduit donc la semantique attendue par TEXT_IO en
;	supprimant d'abord, si le fichier existe. EFI_FILE_PROTOCOL.Delete ferme
;	ET supprime, d'ou l'absence de Close sur ce chemin.
  local c_fail, c_nodel, c_done
  POP_RSI								; @descripteur du nom Ada
  UEFI_NAME_UTF16							; -> UEFI_NAME_BUF, en CHAR16
  UEFI_FS_ROOT
  db 0x48, 0x85, 0xC0						; test rax,rax
  db 0x0F, 0x84							; jz c_fail		volume inaccessible
  dd c_fail - ($ + 4)

			; a) Open( racine, &fichier, nom, READ|WRITE, 0 ) : existe-t-il ?
  db 0x48, 0x89, 0xC1						; mov rcx,rax		racine
  db 0x4C, 0x8B, 0x51, FILE_Open					; mov r10,[rcx+0x08]
  db 0x48, 0x89, 0xE0						; mov rax,rsp
  db 0x48, 0x83, 0xE4, 0xF0						; and rsp,-16
  db 0x48, 0x83, 0xEC, 0x40						; sub rsp,64		(5 arguments : le 5e sur la pile)
  db 0x48, 0x89, 0x44, 0x24, 0x30					; mov [rsp+48],rax
  db 0x48, 0xC7, 0x44, 0x24, 0x20, 0x00, 0x00, 0x00, 0x00		; [rsp+32] = Attributes = 0
  db 0x48, 0x8D, 0x15						; lea rdx,[rip+UEFI_FILE_TMP]
  dd UEFI_FILE_TMP - ($ + 4)
  db 0x4C, 0x8D, 0x05						; lea r8,[rip+UEFI_NAME_BUF]
  dd UEFI_NAME_BUF - ($ + 4)
  db 0x41, 0xB9, EFI_FILE_MODE_RW, 0x00, 0x00, 0x00			; mov r9d,3 : READ|WRITE
  db 0x41, 0xFF, 0xD2						; call r10
  db 0x48, 0x8B, 0x64, 0x24, 0x30					; mov rsp,[rsp+48]
  db 0x48, 0x85, 0xC0						; test rax,rax
  db 0x0F, 0x85							; jnz c_nodel		n'existait pas : rien a supprimer
  dd c_nodel - ($ + 4)

			; fichier->Delete( fichier )
  db 0x48, 0x8B, 0x0D						; mov rcx,[rip+UEFI_FILE_TMP]
  dd UEFI_FILE_TMP - ($ + 4)
  db 0x4C, 0x8B, 0x51, FILE_Delete					; mov r10,[rcx+0x18]
  db 0x48, 0x89, 0xE0						; mov rax,rsp
  db 0x48, 0x83, 0xE4, 0xF0						; and rsp,-16
  db 0x48, 0x83, 0xEC, 0x30						; sub rsp,48
  db 0x48, 0x89, 0x44, 0x24, 0x28					; mov [rsp+40],rax
  db 0x41, 0xFF, 0xD2						; call r10
  db 0x48, 0x8B, 0x64, 0x24, 0x28					; mov rsp,[rsp+40]
c_nodel:
			; b) Open( racine, &fichier, nom, CREATE|READ|WRITE, ARCHIVE )
  UEFI_FS_ROOT
  db 0x48, 0x89, 0xC1						; mov rcx,rax		racine
  db 0x4C, 0x8B, 0x51, FILE_Open					; mov r10,[rcx+0x08]
  db 0x48, 0x89, 0xE0						; mov rax,rsp
  db 0x48, 0x83, 0xE4, 0xF0						; and rsp,-16
  db 0x48, 0x83, 0xEC, 0x40						; sub rsp,64
  db 0x48, 0x89, 0x44, 0x24, 0x30					; mov [rsp+48],rax
  db 0x48, 0xC7, 0x44, 0x24, 0x20, EFI_FILE_ARCHIVE, 0x00, 0x00, 0x00	; [rsp+32] = EFI_FILE_ARCHIVE
  db 0x48, 0x8D, 0x15						; lea rdx,[rip+UEFI_FILE_TMP]
  dd UEFI_FILE_TMP - ($ + 4)
  db 0x4C, 0x8D, 0x05						; lea r8,[rip+UEFI_NAME_BUF]
  dd UEFI_NAME_BUF - ($ + 4)
  db 0x49, 0xB9							; mov r9,EFI_FILE_MODE_CRW	(bit 63 : CREATE)
  dq EFI_FILE_MODE_CRW
  db 0x41, 0xFF, 0xD2						; call r10
  db 0x48, 0x8B, 0x64, 0x24, 0x30					; mov rsp,[rsp+48]
  db 0x48, 0x85, 0xC0						; test rax,rax
  db 0x0F, 0x85							; jnz c_fail
  dd c_fail - ($ + 4)
  db 0x48, 0x8B, 0x05						; mov rax,[rip+UEFI_FILE_TMP]
  dd UEFI_FILE_TMP - ($ + 4)
  db 0xE9							; jmp c_done
  dd c_done - ($ + 4)
c_fail:
  db 0x48, 0xC7, 0xC0, 0xFF, 0xFF, 0xFF, 0xFF			; mov rax,-1
c_done:
  db 0x48, 0x89, 0x45, 0x00						; mov [rbp],rax : handle ou -1
end macro

PATCH 6a  --  SYS_FILE_WRITE
========================================================================================================
--- BLOC A SUPPRIMER ---------------------------------------------------------------------------------
;			--------------
macro			SYS_FILE_WRITE				; WriteFile -> nb octets, ou -1
;			--------------
  local write_fail, write_done
  POP_RDI								; RDI = FILE_ID / HANDLE
  POP_RSI								; RSI = adresse tampon source
  POP_RDX								; RDX = longueur

  ; WriteFile( handle, buffer, length, &written, NULL )
  db 0x41, 0x89, 0xD0						; mov r8d,edx : longueur DWORD
  db 0x48, 0x89, 0xE0						; mov rax,rsp
  db 0x48, 0x83, 0xE4, 0xF0						; and rsp,-16
  db 0x48, 0x83, 0xEC, 0x40						; sub rsp,64
  db 0x48, 0x89, 0x44, 0x24, 0x30					; mov [rsp+48],rax : ancien RSP
  db 0x48, 0xC7, 0x44, 0x24, 0x20, 0, 0, 0, 0				; [rsp+32] = lpOverlapped=NULL
  db 0xC7, 0x44, 0x24, 0x28, 0, 0, 0, 0					; [rsp+40] = written=0
  db 0x48, 0x89, 0xF9						; mov rcx,rdi
  db 0x48, 0x89, 0xF2						; mov rdx,rsi
  db 0x4C, 0x8D, 0x4C, 0x24, 0x28					; lea r9,[rsp+40]
  db 0x31, 0xC0							; xor eax,eax : service non porte -> branche d'echec
  db 0x85, 0xC0							; test eax,eax
  db 0x0F, 0x84							; jz write_fail
  dd write_fail - ($ + 4)
  db 0x8B, 0x44, 0x24, 0x28						; mov eax,[rsp+40] : nb octets ecrits
  db 0xE9								; jmp write_done
  dd write_done - ($ + 4)
write_fail:
  db 0x48, 0xC7, 0xC0, 0xFF, 0xFF, 0xFF, 0xFF				; mov rax,-1
write_done:
  db 0x48, 0x8B, 0x64, 0x24, 0x30					; mov rsp,[rsp+48]
  db 0x48, 0x89, 0x45, 0x00						; mov [rbp],rax
end macro
--- BLOC A INSERER -----------------------------------------------------------------------------------
;			--------------
macro			SYS_FILE_WRITE				; EFI_FILE_PROTOCOL.Write -> nb octets, ou -1
;			--------------
;	Write( fichier, &taille, tampon ). La taille est un UINTN passe PAR ADRESSE
;	et modifie en retour : c'est a la fois le nombre d'octets demandes et le
;	nombre reellement ecrits. D'ou la variable UEFI_IO_SIZE, qui remplace le
;	quatrieme argument &written de WriteFile.
  local w_fail, w_done
  POP_RDI								; RDI = handle = EFI_FILE_PROTOCOL*
  POP_RSI								; RSI = adresse tampon source
  POP_RDX								; RDX = longueur

  db 0x48, 0x89, 0x15						; mov [rip+UEFI_IO_SIZE],rdx
  dd UEFI_IO_SIZE - ($ + 4)
  db 0x48, 0x89, 0xF9						; mov rcx,rdi		1er argument : le fichier
  db 0x4C, 0x8B, 0x51, FILE_Write					; mov r10,[rcx+0x28]
  db 0x48, 0x8D, 0x15						; lea rdx,[rip+UEFI_IO_SIZE]	2e argument
  dd UEFI_IO_SIZE - ($ + 4)
  db 0x49, 0x89, 0xF0						; mov r8,rsi		3e argument : le tampon
  db 0x48, 0x89, 0xE0						; mov rax,rsp
  db 0x48, 0x83, 0xE4, 0xF0						; and rsp,-16
  db 0x48, 0x83, 0xEC, 0x30						; sub rsp,48
  db 0x48, 0x89, 0x44, 0x24, 0x28					; mov [rsp+40],rax
  db 0x41, 0xFF, 0xD2						; call r10
  db 0x48, 0x8B, 0x64, 0x24, 0x28					; mov rsp,[rsp+40]
  db 0x48, 0x85, 0xC0						; test rax,rax		EFI_SUCCESS ?
  db 0x0F, 0x85							; jnz w_fail
  dd w_fail - ($ + 4)
  db 0x48, 0x8B, 0x05						; mov rax,[rip+UEFI_IO_SIZE]	octets ecrits
  dd UEFI_IO_SIZE - ($ + 4)
  db 0xE9							; jmp w_done
  dd w_done - ($ + 4)
w_fail:
  db 0x48, 0xC7, 0xC0, 0xFF, 0xFF, 0xFF, 0xFF			; mov rax,-1
w_done:
  db 0x48, 0x89, 0x45, 0x00						; mov [rbp],rax
end macro

macro			SYS_FILE_CLOSE				; CloseHandle -> 0, ou -1

  POP_RDI								; RDI = HANDLE

  db 0x48, 0x89, 0xE0						; mov rax,rsp
  db 0x48, 0x83, 0xE4, 0xF0						; and rsp,-16
  db 0x48, 0x83, 0xEC, 0x30						; sub rsp,48

;	n'y a pas de Flush separe a appeler. Le contrat rend 0 en cas de succes,

========================================================================================================
CE QUI CHANGE DANS LA NATURE DU SERVICE
========================================================================================================
Linux et Windows offrent un ESPACE DE NOMS GLOBAL : un chemin designe un fichier,
ou qu'il soit. UEFI n'a rien de tel. Ni repertoire courant, ni chemin absolu. On
atteint un fichier par une chaine de protocoles, chacun obtenu du precedent :

  ImageHandle --HandleProtocol(LOADED_IMAGE)--> LoadedImage
              --champ DeviceHandle-----------> le volume d'ou on a demarre
              --HandleProtocol(SIMPLE_FS)----> SimpleFileSystem
              --OpenVolume()-----------------> racine, un EFI_FILE_PROTOCOL
              --Open( nom )------------------> le fichier, meme protocole

Consequence a assumer et a documenter cote Ada : les fichiers sont relatifs au
VOLUME D'AMORCAGE, et a lui seul. Un programme TLALOC lit et ecrit sur la cle qui
l'a charge. Les autres disques existent mais demanderaient LocateHandleBuffer sur
le meme GUID, puis un choix de volume -- ce que la notion Ada de nom de fichier
n'exprime pas.

La chaine n'est parcourue qu'une fois, a la premiere ouverture, et le resultat
garde dans UEFI_FS_ROOT_PTR : un programme qui ne touche aucun fichier ne paie
rien. Le handle rendu a Ada est le pointeur EFI_FILE_PROTOCOL lui-meme, ce qui
preserve le contrat des trois autres cibles : une valeur opaque, ou -1.

========================================================================================================
LE PIEGE DE LA TRONCATURE
========================================================================================================
CreateFileA(CREATE_ALWAYS) de Windows tronque un fichier existant. Open(CREATE)
d'UEFI, NON : il rend le fichier tel quel, avec son ancien contenu au-dela de ce
qu'on ecrira. Un TEXT_IO.CREATE sur un fichier plus long laisserait donc une queue
de donnees mortes, qu'une relecture ulterieure prendrait pour du contenu.

D'ou la sequence en deux temps de SYS_FILE_CREATE : ouvrir sans CREATE pour voir
si le fichier existe, et le cas echeant appeler EFI_FILE_PROTOCOL.Delete -- qui
ferme ET supprime, d'ou l'absence de Close sur ce chemin -- avant de creer.
Verifie : un fichier de 59 octets reecrit avec 7 octets en fait bien 7 ensuite.

========================================================================================================
MESURES
========================================================================================================
  handle rendu par CREATE  : 000000001E7F24A0   (pointeur EFI_FILE_PROTOCOL)
  octets rendus par WRITE  : 000000000000003B   (59, longueur exacte du texte)
  code rendu par CLOSE     : 0000000000000000

  mdir  : ESSAI    TXT        59 2026-09-16  20:49
  mtype : Bonjour depuis UEFI, sans OS.
          Deuxieme ligne du fichier.

  puis reecriture courte :  ESSAI    TXT         7      -> COURT

L'horodatage du fichier vient de la RTC via le pilote FAT du firmware : la date
est juste, ce qui recoupe le palier precedent.

========================================================================================================
UN PIEGE RENCONTRE EN ECRIVANT LE TEST
========================================================================================================
Ne pas garder un handle de fichier dans RBX entre deux services. UEFI_WRITE_STDOUT
s'en sert comme compteur de boucle, donc tout SYS_PUT_STR ou SYS_PUT_CHAR le
detruit. C'est conforme au contrat -- RBX est un registre de travail de la LLIR --
mais le symptome est spectaculaire : handle nul, donc lecture d'une vtable a
l'adresse 0x28, donc saut dans le decor et #UD. Un programme Ada ne rencontre pas
le probleme, ses variables etant sur la pile LLIR.
