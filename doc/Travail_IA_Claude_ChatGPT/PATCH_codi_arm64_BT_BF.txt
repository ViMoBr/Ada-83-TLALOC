LIVRAISON : codi_arm64.finc -- BT/BF forme longue (plage +-128 Mo)
=====================================================================

Fichier cible : codi_arm64.finc (version jointe a la demande, 2482 lignes).
Format : une modification = ANCRE (ligne existante unique, inchangee) +
bloc A SUPPRIMER (texte existant exact, tabulations comprises) + bloc DE
REMPLACEMENT. Le bloc a supprimer commence sur la ligne qui suit
immediatement l'ancre (une ligne de tirets, non unique, est laissee en
place entre l'ancre et le bloc supprime : elle est signalee).
Les tabulations sont preservees telles quelles (fichier a copier, ne pas
retaper). Le texte nouveau est ASCII pur ; seuls les blocs SUPPRIMES
reproduisent le caractere +- (0xC2 0xB1) deja present dans le fichier.

Diagnostic
----------
BT/BF emettent CBNZ/CBZ x0, lbl : immediat imm19, plage +-1 Mo. En
assemblant le compilateur entier, `BT STANDARD.ne_raise_` (_STANDRD.FINC
ligne 1175) vise le trampoline ne_raise_ a plus de 1 Mo : l'assert de
plage echoue a chaque passe, d'ou le message fasmg. BRA (B, imm26) a
deja +-128 Mo ; les autres CBZ/CBNZ/B.cond du fichier sont tous
intra-macro (cibles locales, quelques instructions) et ne sont pas
concernes.

Correctif retenu : forme longue SYSTEMATIQUE par inversion de condition
(CBZ/CBNZ x0, +8 enjambe un B lbl). Meme doctrine que sur x86-64 ou BT/BF
sont rel32 systematiques (pieges n. 82 et 88) : aucune decision de
taille inter-passes, donc aucun risque d'oscillation fasmg. Cout : +4
octets par BT/BF. La semantique est inchangee (test de x0 entier, 64
bits, comme avant).

Encodages (verifies par desassemblage) :
  0xB4000040  cbz  x0, .+8
  0xB5000040  cbnz x0, .+8
  B lbl : emis par la macro BRA existante (disp = lbl - $ + 4, assert
  imm26), exactement 4 octets, ce qui justifie le +8.

COMMIT 1 : arm64 -- BT/BF forme longue par inversion + B (plage +-128 Mo)

---------------------------------------------------------------------
MODIF 1/2 -- macro BT
---------------------------------------------------------------------
ANCRE (ligne 1440, unique, inchangee) :
<<<
macro			BT	lbl				; branch true
>>>
(La ligne suivante ";<tab><tab><tab>-------------" reste en place.)

A SUPPRIMER (lignes 1442 a 1449, jusqu'a "end macro" inclus) :
<<<
;	POP x0 puis CBNZ x0, lbl (sauter si x0 != 0).
;	CBNZ a une plage limitee a ±1 Mo (imm19). Suffisant pour les programmes courants.
  POP_RAX
  local disp
  dd 0xB5000000 or (((disp shr 2) and 0x7FFFF) shl 5)			; cbnz x0, lbl
  disp = lbl - $ + 4
  assert (disp mod 4) = 0 & disp >= -1048576 & disp <= 1048572
end macro
>>>

REMPLACEMENT :
<<<
;	POP x0 puis saut par INVERSION : CBZ x0, +8 enjambe le B ; B lbl.
;	Un CBNZ direct n'offre que +-1 Mo (imm19) : insuffisant pour le compilateur
;	entier (BT STANDARD.ne_raise_ hors plage). Le B offre +-128 Mo (imm26),
;	comme BRA, dont on reutilise la macro (et son assert de plage).
;	Forme longue SYSTEMATIQUE : jamais de choix de taille inter-passes
;	(pieges n. 82 et 88 : decision non monotone = oscillation fasmg).
;	Cout : une instruction (4 octets) de plus par BT/BF.
  POP_RAX
  dd 0xB4000040							; cbz x0, +8	(x0 = 0 : enjambe le B, pas de saut)
  BRA lbl								; b lbl		(x0 /= 0 : saut)
end macro
>>>

  POP_RAX

>>>

REMPLACEMENT :
<<<
;	Symetrique de BT : CBNZ x0, +8 enjambe le B ; B lbl.
  POP_RAX
  dd 0xB5000040							; cbnz x0, +8	(x0 /= 0 : enjambe le B, pas de saut)
  BRA lbl								; b lbl		(x0 = 0 : saut)
end macro
>>>

ORACLE DU COMMIT 1
---------------------------------------------------------------------
O1 (bloquant) : l'assemblage du compilateur entier passe :
    ./fasmg -v 2 -p 20 ./ADA_COMP.arm64fas ./ADA_COMP.arm64exe
  -> plus d'erreur de passes ni d'assert ; le nombre de passes doit
  rester celui d'avant (typiquement 2-3), signe qu'aucune oscillation
  n'a ete introduite.
O2 (taille) : pour un executable de test deja assemble avant correctif,
  la taille du code croit d'exactement 4 * (nombre de BT + BF emis).
  Comptage : grep -c "^[[:space:]]*B[TF][[:space:]]" sur le .fas et ses
  includes (ou simplement sur le FINC de l'unite de test).
O3 (semantique, non-regression) : rejouer les temoins existants a
  branchements (if / while / and then / or else / membership / checks
  ce_raise_ et ne_raise_ -- division par zero) sur la cible arm64 :
  sorties octets identiques a celles d'avant correctif. Le test de
  division par zero doit encore lever NUMERIC_ERROR (c'est precisement
  le BT ne_raise_ qui echouait a s'assembler).
O4 (spot-check binaire, facultatif) : sur la cible,
    objdump -D -b binary -m aarch64 ADA_COMP.arm64exe | grep -B1 -A1 "cbz.*x0"
  chaque cbz/cbnz x0 issu de BT/BF est immediatement suivi d'un b, et
  sa cible est l'instruction qui suit ce b (+8).
