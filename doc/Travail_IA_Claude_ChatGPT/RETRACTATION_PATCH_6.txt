DIAGNOSTIC DE LA RETRACTATION
-----------------------------
Le patch n 6 reposait sur une lecture FAUSSE de la semantique de LIx en
forme depilee.  LIa (lvl = -1, disp = 0, ofs = 0) fait DEUX acces
memoire, pas un : INDIRECT_BASE depile l'adresse et lit [pop+disp],
puis le LOAD lit [resultat+ofs].  Le thunk d'origine -- LIa seul --
realisait donc deja slot -> doublet -> data, exactement le contrat.

Preuve RUNTIME, dans la ligne strace du meme appel :
	read(3, NULL, 26644)
fd = 3 est CORRECT -- il est extrait par "LId , 0, _FILE_TYPE.ID", le
meme motif a deux dereferences sur le doublet de BIN_FILE.  Meme
mecanique, meme profondeur : FILE arrivait juste, ITEM arrivait juste.
Le "La , 0" ajoute par le patch n 6 faisait une TROISIEME deref :
[@data+0] = les 8 premiers octets du record GRMR encore vierges = 0
-> read(3, NULL, ...) -> EFAULT -> END_ERROR.

Le watchpoint (GRMR_disp ecrit une seule fois par l'elaboration, jamais
ecrase) a fourni la contradiction qui a force cette relecture.

Chronologie reordonnee : l'END_ERROR d'AVANT le patch n 6 etait deja le
pur desaccord de tailles (SIZE_BYTES 26644 vs fichier 21328), avec une
adresse VALIDE -- jamais observee parce que le db 0xCC tuait strace a
l'epoque.
