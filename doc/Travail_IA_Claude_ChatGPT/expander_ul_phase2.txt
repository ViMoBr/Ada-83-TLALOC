=======================================================================================================================
EXPANDER — PHASE 2 : TAILLES DE CONTENEURS NON SIGNES ET OBEISSANCE A 'SIZE
=======================================================================================================================

Decoupage en 5 pas, chacun avec son oracle. Les pas 0 a 3 sont NEUTRES
(oracle : .finc strictement identiques, ou L->UL seulement). Le pas 4 est le
flip : c'est le SEUL endroit ou les tailles changent, et son perimetre est
limite aux DN_INTEGER (les enumeres > 127 litteraux viendront apres, en lot
separe, via CODE_ENUMERATION_DECL).


-----------------------------------------------------------------------------------------------------------------------
PAS 0 — VERIFICATION PREALABLE DE LA PHASE 1 (5 minutes, avant tout collage)
-----------------------------------------------------------------------------------------------------------------------
Verifier que des ULb/ULw apparaissent BIEN dans le .finc genere d'un temoin
`type T is range 0 .. 255;` avec une variable lue. Si AUCUN UL n'apparait,
c'est que le predicat rend toujours FALSE : la SM_RANGE du type de BASE
(anonyme, RM83 3.5.4) peut etre VOID alors que celle du sous-type de premiere
declaration existe. Correctif dans IS_UNSIGNED_TYPE :

CHERCHER :
      RNG := D( SM_RANGE, BASE );
      if  RNG = TREE_VOID  or else  RNG = TREE_NIL  then
        return FALSE;
      end if;
REMPLACER :
      RNG := D( SM_RANGE, BASE );
      if  RNG = TREE_VOID  or else  RNG = TREE_NIL  then
        RNG := D( SM_RANGE, TS );						-- base anonyme sans range : celle du
      end if;									-- sous-type de 1ere declaration (meme gamme)
      if  RNG = TREE_VOID  or else  RNG = TREE_NIL  then
        return FALSE;
      end if;

Oracle : les UL apparaissent, filet toujours vert (toujours neutre : movzx==movsx).

-----------------------------------------------------------------------------------------------------------------------
PAS 2 — OPER_SIZ_CHAR RESOLU SUR LE TYPE DE BASE (expander-utils.adb)
-----------------------------------------------------------------------------------------------------------------------
La representation d'un sous-type est celle de sa base (RM83). Centraliser la
resolution ici couvre d'un coup les sous-types nommes, ANONYMES et actuels
generiques : tout consommateur de OPER_SIZ_CHAR suivra le flip sans retouche.

CHERCHER (corps de OPER_SIZ_CHAR) :
    declare
      SIZ		: NATURAL		:= DI( CD_IMPL_SIZE, DEFN );
    begin
REMPLACER :
    declare
      TS	: TREE	:= DEFN;
      SIZ	: NATURAL;
    begin
      if  TS.TY = DN_INTEGER  or else  TS.TY = DN_ENUMERATION  then		-- la representation vit sur la BASE (RM83) ;
        declare									-- un sous-type suit sa base, toujours
	BASE	: TREE	:= D( SM_BASE_TYPE, TS );
        begin
	if  BASE /= TREE_VOID  and then  BASE /= TREE_NIL  then
	  TS := BASE;
	end if;
        end;
      end if;
      SIZ := DI( CD_IMPL_SIZE, TS );

(le reste du corps inchange ; les messages d'erreur peuvent rester sur DEFN)

Oracle STRICT : les .finc generes de toute la suite doivent etre IDENTIQUES A
L'OCTET PRES a l'etat d'avant ce pas. La moindre difference signifierait que
le front-end pose parfois des CD_IMPL_SIZE differents base/sous-type — a
investiguer AVANT de continuer, ce serait un bug latent aujourd'hui meme.


-----------------------------------------------------------------------------------------------------------------------
PAS 3 — COPIE CD_IMPL_SIZE base -> sous-type dans CODE_SUBTYPE_DECL (types_decls)
-----------------------------------------------------------------------------------------------------------------------
Pour les lecteurs DIRECTS de CD_IMPL_SIZE qui ne passent pas par OPER_SIZ_CHAR
(COMP_SIZE_BITS quand le composant est un sous-type nomme, le patron LI de SIZ
du sous-type, TYPE_SIZE). Coller apres "DB( CD_COMPILED,  TYPE_SPEC, TRUE );" :

    if  TYPE_SPEC.TY = DN_INTEGER  or else  TYPE_SPEC.TY = DN_ENUMERATION  then
      declare									-- representation = celle de la base :
        BASE	: TREE	:= D( SM_BASE_TYPE, TYPE_SPEC );				-- recopier pour les lecteurs directs
      begin									-- de CD_IMPL_SIZE (COMP_SIZE_BITS...)
        if  BASE /= TREE_VOID  and then  BASE /= TREE_NIL  then
	DI( CD_IMPL_SIZE, TYPE_SPEC, DI( CD_IMPL_SIZE, BASE ) );
        end if;
      end;
    end if;

L'elaboration Ada garantit que la base est declaree (et compilee, donc flippee
au pas 4) avant tout sous-type d'elle.

Oracle : .finc identiques (la copie est un no-op tant que base == sous-type).


-----------------------------------------------------------------------------------------------------------------------
PAS 4 — LE FLIP : CODE_INTEGER_DECL (types_decls) — ICI les tailles changent
-----------------------------------------------------------------------------------------------------------------------

4a. Dans le declaratif, retirer l'initialisation (elle lirait la taille AVANT
    l'ecriture en retour) :
CHERCHER :
    SIZE_CHAR		: CHARACTER	:= OPER_SIZ_CHAR( INTEGER_SPEC );
REMPLACER :
    SIZE_CHAR		: CHARACTER;						-- affecte APRES l'ecriture du conteneur

4b. Coller apres "DB( CD_COMPILED,  INTEGER_SPEC, TRUE );" :

			-- Taille du conteneur backend, ecrite en retour dans CD_IMPL_SIZE
			-- sur le sous-type de 1ere declaration ET sa base anonyme
			-- (miroir du double CD_LEVEL ci-dessus). Priorites :
			--   1. length clause 'SIZE : obeir (RM83 13.2) ;
			--   2. type non signe : conteneur minimal NON signe (8/16) ;
			--   3. sinon : taille minimale signee du front-end, inchangee.
		CONTAINER_SIZE:
    declare
      SIZE_BITS	: INTEGER	:= DI( CD_IMPL_SIZE, INTEGER_SPEC );
      LST	: TREE		:= EXP_LST;
    begin
      if  D( SM_SIZE, INTEGER_SPEC ) /= TREE_VOID  then
        SIZE_BITS := DI( SM_SIZE, INTEGER_SPEC );

      elsif  D( SM_SIZE, D( SM_BASE_TYPE, INTEGER_SPEC ) ) /= TREE_VOID  then
        SIZE_BITS := DI( SM_SIZE, D( SM_BASE_TYPE, INTEGER_SPEC ) );

      elsif  IS_UNSIGNED_TYPE( INTEGER_SPEC )  then
        while  LST.TY = DN_PARENTHESIZED  or else  LST.TY = DN_CONVERSION  loop	-- meme deshabillage que le predicat
	LST := D( AS_EXP, LST );
        end loop;
        if  LST.TY = DN_NUMERIC_LITERAL  then
	if    DI( SM_VALUE, LST ) <= 2**8  - 1  then  SIZE_BITS := 8;
	elsif DI( SM_VALUE, LST ) <= 2**16 - 1  then  SIZE_BITS := 16;
	end if;									-- au-dela : la taille signee du front-end
        end if;									-- donne deja le bon conteneur d/q
      end if;

      DI( CD_IMPL_SIZE, INTEGER_SPEC, SIZE_BITS );
      DI( CD_IMPL_SIZE, D( SM_BASE_TYPE, INTEGER_SPEC ), SIZE_BITS );
    end	CONTAINER_SIZE;

    SIZE_CHAR := OPER_SIZ_CHAR( INTEGER_SPEC );


-----------------------------------------------------------------------------------------------------------------------
PAS 5 — TEMOINS ET AUDITS POST-FLIP
-----------------------------------------------------------------------------------------------------------------------
Temoin dedie (a mettre dans les tests auto jugeants) :
  type AC_BYTE is range 0..255;  for AC_BYTE'SIZE use 8;
  subtype HALF is AC_BYTE range 0..127;
  type TBL is array (1..10) of AC_BYTE;
  1. V : AC_BYTE := 255 ; verifier V = 255, V > 100, INTEGER(V) = 255
  2. for I in AC_BYTE loop ... (borne LMT_ en patron b, ULb, terminaison !)
  3. AC_BYTE'FIRST / 'LAST / 'SIZE ; HALF'LAST
  4. range check qui DOIT lever : AC_BYTE(300), et un qui ne doit pas : AC_BYTE(255)
  5. TBL en record (mini-GRMR) : offsets et taille

Diffs .finc ATTENDUS sur le temoin (tout le reste identique) :
  _AC_BYTE : LI 8 (au lieu de 16), VAR FST, b / VAR LST, b
  _TBL : COMP_SIZ 8, SIZ = 8*10
  loads en ULb, stores en Sb, STATOFS retombes a la taille octets
  GRMR : LI 213152 -> LI 170656 ; STATOFS AC_SYM 4800, NTER_* 255 ; size 21332

Audits :
  a. dump COMP_SIZ des tableaux dont le composant est un SOUS-TYPE nomme et un
     sous-type ANONYME de AC_BYTE ;
  b. conversions croisees AC_BYTE <-> INTEGER <-> AC_SHORT dans les 2 sens ;
  c. AC_BYTE en parametre in, out, in out (piege n 80 relu en ULIb) ;
  d. AC_BYTE en actuel generique (micro-procedures LD/ST, pieges 36/37) ;
  e. ACVC : re-passer, en surveillant particulierement c34/c35 (types scalaires)
     et tout ce qui touche 13.2 si present dans le harnais.

HORS PERIMETRE de ce lot (a ouvrir ensuite, dans l'ordre) :
  - enumerations > 127 litteraux et 'SIZE sur enumeres : meme geste dans
    CODE_ENUMERATION_DECL (attention MIN_REP negatif : rester signe dans ce cas) ;
  - STATOFS 3e parametre algn (alignement par composant, AC_SYM sans padding) ;
  - unification STATIC_SIZE / size=$ (stride des tableaux de records).
