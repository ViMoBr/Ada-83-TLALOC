CHANTIER PREFIXE CONVERSION-VUE -- TREE(X).COMP
expander-expressions.adb, CODE_SELECTED/RECURSE_SELECTED. 2 blocs.

Fossile : SET_UTIL.IS_NULLARY -- `TREE(DEFINTERP).TY = DN_NULLARY_CALL`
emettait LI 230 / CEQ SANS l'operande gauche : le predicat comparait
230 a un fond de pile. Quatrieme bug latent vivant paye au recensement
(sem_phase auto-compile : IS_NULLARY & co repondaient au hasard).

PRINCIPE : entre records de MEME RACINE DE DERIVATION (DEFINTERP_TYPE
is new TREE -- la famille du chantier n 117), la conversion est une
conversion-VUE : meme representation, transparente pour l'ADRESSAGE.
On la fait disparaitre du prefixe en rebranchant NAME sur l'operande ;
PROCESS_DESIGNATOR lit la variable NAME et retrouve alors son chemin
nominal habituel (param composite : La -X_ofs, La -1,0, extraction
rep du composant -- celui de TREE, ou sem a resolu le designator).
HYPOTHESE DOCUMENTEE : pas de clause de rep PROPRE sur les derives
(vrai du corpus) ; une derivee re-representee exigerait un
reformatage des donnees = autre chantier, et toute conversion hors
meme-racine reste un TROU nomme.
========================================================================


------------------------------------------------------------------------
BLOC 1 -- le chasseur de racine. ANCRE (declarations de
RECURSE_SELECTED) :
      NAME		: TREE		:= D( AS_NAME, SELECTED );
COLLER APRES (avant PROCESS_DESIGNATOR) :
------------------------------------------------------------------------

		-----------
      function	ROOT_RECORD	( T :TREE )	return TREE
      is		-----------
      -- Racine de derivation d'une vue record : depouille les vues
      -- (FULL_TYPE_VIEW), remonte contrainte -> base puis la chaine
      -- SM_DERIVED. TREE_VOID si la vue n'aboutit pas a un DN_RECORD.
        TS	: TREE	:= CODI.FULL_TYPE_VIEW( T );
      begin
        loop
	if  TS = TREE_VOID  then
	  return  TREE_VOID;
	elsif  TS.TY = DN_CONSTRAINED_RECORD  then
	  TS := CODI.FULL_TYPE_VIEW( D( SM_BASE_TYPE, TS ) );
	elsif  TS.TY = DN_RECORD  and then  D( SM_DERIVED, TS ) /= TREE_VOID  then
	  TS := CODI.FULL_TYPE_VIEW( D( SM_DERIVED, TS ) );
	elsif  TS.TY = DN_RECORD  then
	  return  TS;
	else
	  return  TREE_VOID;
	end if;
        end loop;
      end	ROOT_RECORD;
	-----------


------------------------------------------------------------------------
BLOC 2 -- la normalisation du prefixe, en tete du tri.
------------------------------------------------------------------------
AVANT :
      if  NAME.TY = DN_SELECTED  then
        RECURSE_SELECTED( NAME ) ;
        PROCESS_DESIGNATOR;
APRES :
      -- Prefixe en CONVERSION-VUE : TREE(X).COMP (SET_UTIL, derives
      -- prives de TREE, famille n 117). Meme racine de derivation =
      -- meme representation (hypothese : pas de rep propre sur les
      -- derives) : la conversion est transparente pour l'adressage,
      -- on rebranche NAME sur l'operande et le tri reprend. La boucle
      -- absorbe les conversions imbriquees ; hors meme-racine : TROU.
      while  NAME.TY = DN_CONVERSION  loop
        declare
	RA	: TREE	:= ROOT_RECORD( D( SM_EXP_TYPE, NAME ) );
        begin
	if  RA /= TREE_VOID
	and then  RA = ROOT_RECORD( D( SM_EXP_TYPE, D( AS_EXP, NAME ) ) )
	then
	  NAME := D( AS_EXP, NAME );

	else
	  TROU( "RECURSE_SELECTED conversion prefixe non transparente", NAME );
	  return;
	end if;
        end;
      end loop;

      if  NAME.TY = DN_SELECTED  then
        RECURSE_SELECTED( NAME ) ;
        PROCESS_DESIGNATOR;

NOTES
========================================================================
1. POURQUOI EN TETE DU TRI et pas une branche de plus : la conversion
   peut envelopper N'IMPORTE QUEL prefixe -- TREE(X).A, TREE(X.Y).Z,
   TREE(F(N)).C -- et le tri doit reprendre sur l'operande revele.
   La boucle while (plutot qu'un if) absorbe aussi R2(R1(X)).A.
   PROCESS_DESIGNATOR lisant la variable NAME, le rebranchement est
   invisible pour tout l'aval.

2. LA GARDE MEME-RACINE est volontairement du cote bruyant : une
   conversion legitime que ROOT_RECORD ne saurait pas prouver (vue
   exotique, rep propre un jour) tombera en TROU nomme -- jamais en
   emission silencieusement fausse. C'est la regle de tous les
   correctifs de cette campagne.

3. TEMOIN TROU_CONV1 (avant SET_UTIL) -- jumelles n 110 :
     - type R ... + rep clause ; type RD is new R (prive) ;
       fonction IS_A( X :RD ) return BOOLEAN is
         begin return R( X ).A = 5; end;         -- le cas IS_NULLARY
     - meme paire SANS rep clause ;
     - imbrications : R( X ).A + R( MK( N ) ).B (conversion sur appel,
       exerce la branche DN_FUNCTION_CALL derriere la boucle) ;
     - variables ET parametres in (les deux chemins nominaux de
       PROCESS_DESIGNATOR).
4. ORACLES : TROU_SEL_CONV vert en STRICT ; set_util re-expanse en
   STRICT -> zero TROU, le FINC d'IS_NULLARY montre desormais
   La 1, -DEFINTERP_ofs / La -1, 0 / <extraction rep de TY> AVANT
   LI 230 / CEQ / Sb ; filet + auto-compilation (sem_phase etait
   faux : meme consigne aval que HASH_SEARCH, re-derouler depuis le
   compilateur de reference).
5. CE TROU CLOS LE RECENSEMENT INITIAL : si le run corpus complet ne
   crie plus, consigner dans ETAT_PILIERS (carnet de dettes : 'VALUE
   enum, tasking, rep-clauses restantes, deref implicite), passer le
   defaut en STRICT, et verser l'entree PIEGES « discipline TROU() »
   avec ses quatre fossiles payes au recensement : le contrat
   attribut-fonction invisible, HASH_SEARCH (CEQ sur fond de pile),
   IS_NULLARY (idem via conversion), et les gardes TREE_VOID.
