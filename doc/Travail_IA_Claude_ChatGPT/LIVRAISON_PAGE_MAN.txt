LIVRAISON PAGE_MAN : CACHE DE PAGES EN MEMOIRE (29 aout 2026)
================================================================

Constat (strace -f -c sur expander-expressions.adb, VisionFive 2) : 1 602 057 read,
925 070 write, 1 365 563 lseek pour une unite de 1 054 lignes ; 3,9 millions de
syscalls, 27 s de temps noyau sur 81 s. Le cache de page_man fait 50 pages de
512 octets (25 Kio) pour un arbre DIANA de plusieurs Mio : chaque acces au-dela
du cache est un defaut (lseek + read), chaque eviction d'une page modifiee un
lseek + write. Le mecanisme d'ecriture differee (CHANGED / FREE_PAGE) existe
deja ; c'est la taille du cache qui est le probleme.

Un seul commit, deux fichiers, deux modifications. ASCII pur, tabulations
preservees. Ordre d'application indifferent ; les deux vont ensemble
(la seconde est OBLIGATOIRE des que MAX_RPG grandit, voir C-P2).

------------------------------------------------------------------------
COMMIT C-P1 -- MAX_RPG 50 -> 8192 (idl.adb, spec de PAGE_MAN)
------------------------------------------------------------------------

Fichier : src/.../idl.adb (package body IDL, package PAGE_MAN)

Modification C-P1.1

ANCRE (texte existant, unique, inchange) :
    subtype VPG_NUM			is VPG_IDX  range 1 .. MAX_VPG;


SUPPRIMER (le bloc qui suit immediatement l'ancre) :
    MAX_RPG			: constant	:= 50;						--| PAGES PHYSIQUES (REELLES)

REMPLACER PAR :
    MAX_RPG			: constant	:= 8192;						--| PAGES PHYSIQUES (REELLES) : 4 Mio de cache, la
												--| pagination sur disque ne sert plus qu'a la persistance

Note : 8192 x 512 = 4 Mio, pris sur le tas de 64 Mio (HEAP_ALLOC), une seule
fois (C-P2). Les secteurs jamais utilises ne sont jamais touches : le noyau
ne leur alloue pas de page physique. Si PAGE_IDX'LAST (nombre max de pages
virtuelles) est <= 65536, on peut aller jusqu'a MAX_RPG := MAX_VPG et l'arbre
tient alors entierement en memoire (au plus 32 Mio) : plus AUCUN defaut de
page, le fichier n'est ecrit qu'a la fermeture.

------------------------------------------------------------------------
COMMIT C-P1 (suite) -- allocation unique des secteurs (idl-page_man.adb)
------------------------------------------------------------------------

Fichier : src/communs/idl-page_man.adb, procedure INIT_PAGE_MAN

Pourquoi c'est obligatoire : INIT_PAGE_MAN est appelee a CHAQUE
CREATE_PAGE_MANAGER / OPEN_PAGE_MANAGER (unite compilee, puis chaque unite
de bibliotheque relue), et l'agregat (others => (... DATA => new SECTOR))
evalue le new une fois par composant a chaque appel. Le tas TLALOC est un
bump-pointer sans liberation : 50 pages, c'etait 25 Kio perdus par
ouverture ; a 8192 ce serait 4 Mio par ouverture et le tas de 64 Mio
deborderait au bout d'une quinzaine d'unites relues. On alloue donc le
secteur seulement s'il ne l'a pas encore ete (DATA vaut null a
l'elaboration, valeur par defaut des acces en Ada 83).

Modification C-P2.1

ANCRE (texte existant, unique, inchange) :
  ASSOC_PAGE := (others=> 0);								--| POUR TOUTE PAGE VIRTUELLE, PAS DE PAGE REELLE ASSOCIEE

SUPPRIMER (le bloc qui suit immediatement l'ancre) :
  PAG	   := (others=> (	VP		=> 0,					--| INITIALISER LA TABLE DES PAGES PHYSIQUES
			AREA		=> 0,
			RECUPERABLE	=> TRUE,
			CHANGED		=> FALSE,
			DATA		=> new SECTOR )
			);

REMPLACER PAR :
  for RP in RPG_NUM loop								--| INITIALISER LA TABLE DES PAGES PHYSIQUES
    if PAG( RP ).DATA = null then							--| LE SECTEUR N'EST ALLOUE QU'UNE FOIS (TAS SANS LIBERATION :
      PAG( RP ).DATA := new SECTOR;							--| UN NEW PAR OUVERTURE FUIRAIT MAX_RPG*512 OCTETS)
    end if;
    PAG( RP ).VP		:= 0;
    PAG( RP ).AREA		:= 0;
    PAG( RP ).RECUPERABLE	:= TRUE;
    PAG( RP ).CHANGED		:= FALSE;
  end loop;

------------------------------------------------------------------------
ORACLES
------------------------------------------------------------------------

1. Compilation d'ADA_COMP (x86 T2) puis point fixe : les .FINC produits
   par le nouveau compilateur sur toute la chaine doivent etre
   byte-identiques a ceux d'avant (diff_finc.sh) -- la pagination est
   transparente pour le contenu de l'arbre, seul l'ordre des ecritures
   disque change.

2. strace -f -c ./T1.riscv64exe (meme ligne d'arguments,
   expander-expressions.adb W) : attendu, read/write/lseek ramenes de
   3,9 millions a l'ordre de quelques dizaines de milliers (les read du
   source, 45 000, dominent alors), et "Ok N msec" en baisse de 25 a 35 %.
   Si les defauts de page restent nombreux (write >> HIGH_VPG), c'est que
   l'arbre depasse 8192 pages : monter MAX_RPG (cf. note C-P1).

3. Enchainement d'une vingtaine d'unites (compilation du compilateur) sans
   croissance du tas : temoin que C-P2 fait son office (sans elle, HEAP
   deborde -> segfault vers la 15e unite).

Fichiers de controle joints : idl.adb.new et idl-page_man.adb.new, resultat
exact de l'application des deux modifications (a comparer par cmp).
