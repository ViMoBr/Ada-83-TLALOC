RAPPEL DU DIAGNOSTIC
--------------------
Le FINC d'ADA_COMP montre, pour les DEUX seules cibles d'affectation
qualifiees de package du bloc (IDL.PROJECT_PATH_LENGTH puis
IDL.LIB_PATH_LENGTH), un motif unique :

	Ld	0, STANDARD.IDL.PROJECT_PATH_LENGTH_disp	; VALEUR (0) !
	<calcul de la nouvelle valeur>
	Sd						; nu

Semantique du Sd nu (codi : POP_RBX donnee, puis BASE_IN_RAX lvl=-1 =
POP_RAX adresse) : [adresse] := donnee.  L'"adresse" empilee est la
VALEUR COURANTE du scalaire (0 a l'elaboration) -> mov [0], n ->
segfault, pile a la position observee (apres les deux boucles
FIND_START_1 / FIND_POST_END_1).

Cause : la branche DN_VARIABLE_ID de PROCESS_DESIGNATOR emet, pour un
designateur scalaire, "L<siz> lvl, path X_disp" (la valeur) SANS
consulter IS_SOURCE -- alors que les branches DN_COMPONENT_ID testent
IS_SOURCE partout (Lx vs LVA, LIx vs LIVA).  En destination
(IS_SOURCE => FALSE, contrat de l'affectation et de
CODE_OBJECT_ADDRESS), il faut l'ADRESSE du slot : LVA.
Le cas "affectation a un scalaire d'un autre package" n'avait jamais
ete exerce avant le main d'ADA_COMP.

Le meme trou couvrait les variables ACCESS (la "valeur" d'un pointeur
etant une adresse, l'ecriture aurait clobbere le POINTE au lieu du
pointeur -- corruption silencieuse, pire qu'un segfault) : la nouvelle
branche les traite ensemble, comme le font les branches composant.

        if  DESIGNATOR_DEFN.TY = DN_VARIABLE_ID  then

	if  ( D( SM_EXP_TYPE, DESIGNATOR ).TY in CLASS_SCALAR

NOTES DE LECTURE
------------------------------------------------------------------------
1. FINC attendu apres recompilation, aux deux sites d'ADA_COMP :

	LVA	0, STANDARD.IDL.PROJECT_PATH_LENGTH_disp	; @slot
	<calcul>
	Sd

   (idem LIB_PATH_LENGTH).  Les LECTURES de ces memes variables
   ("Ld 0, ...PROJECT_PATH_LENGTH_disp" dans les calculs de longueurs)
   restent inchangees : elles passent par IS_SOURCE = TRUE.

2. Beneficiaires collateraux : CODE_OBJECT_ADDRESS( PKG.X ) pour X
   scalaire (parametres OUT/IN OUT qualifies de package) rendait lui
   aussi la valeur au lieu de l'adresse -- repare par le meme trou
   bouche, puisqu'il passe par CODE_SELECTED( IS_SOURCE => FALSE ).

3. Le tableau voisin (IDL.LIB_PATH(1..N) := ... & ...) n'est PAS
   concerne : la branche composite emet "La lvl, X_disp" = pointeur de
   donnees, correct en source comme en destination (BLKMOV).

4. DETTE RELEVEE, non traitee ici : le chemin d'affectation a cible
   selectionnee n'emet PAS le check de sous-type (comparer : le store
   direct "Sd 1, ACCES_TEXTE_LENGTH_disp" est precede des checks
   _NATURAL.FST/LST, le store selectionne n'a rien).  A verser au
   pilier checks (idiome DUP/CLT/BT insertable, note E-C) quand le
   bootstrap respirera.

5. CANDIDAT PIEGE : "PROCESS_DESIGNATOR : toute branche de designateur
   doit distinguer IS_SOURCE.  Une emission de VALEUR la ou le contrat
   destination attend une ADRESSE ne casse rien a la compilation et
   ecrit a l'adresse <valeur> a l'execution ; pour un ACCESS c'est une
   corruption du pointe, silencieuse.  Temoin : DN_VARIABLE_ID scalaire
   qualifie de package, premier exerce par le main d'ADA_COMP."
