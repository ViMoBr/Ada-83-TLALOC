========================================================================================================================
LOT E-SEL-02  --  expander : correctif du correctif E-SEL-01 (forme du resultat : @data, pas @doublet)
========================================================================================================================

DIAGNOSTIC (symptome : `placement STR incoherent P2B/P3 : EXC_NL__` sur ADA_COMP et TARGET_CODE).
EXC_NL__ est le dernier differe enregistre, donc le PREMIER place/emis (LIFO) : l'echec au
premier STR signifie que la fin du code differe entre P2B et P3 alors que chaque element a
passe le contrat SIZE_OF = octets emis.  Seule cause possible : le POINT DE DEPART de P2B,
ENTRY_PT + TR.PROLOGUE_SIZE, est faux -- TR est mal rempli.  Et il l'est par ma faute :
E-SEL-01 fait passer PKG.CST composite par CODE_VC_ID, qui laisse l'@DOUBLET (LVA X_disp,
comme le nom simple).  Or CODE_COMPOSITE_DATA_ADDRESS n'ajoute le `LA` (doublet -> data)
QUE pour DN_USED_OBJECT_ID / FUNCTION_CALL / QUALIFIED / STRING_LITERAL : un DN_SELECTED
composite doit deja laisser @DATA -- c'est ce qu'emet la branche DN_VARIABLE_ID composite
juste au-dessus (`LA lvl, REGIONS_PATH X_disp`, = data_ptr).  Le BLKMOV de `TR := TRAITS`
copiait donc le doublet (data_ptr, info_ptr) puis 24 octets de suite : E_MACHINE,
PROLOGUE_SIZE, BRA_SIZE etaient des morceaux de pointeurs.

Les applications de C0 sont hors de cause : le symptome est entierement explique ici.

REMEDE : dans la branche composite d'E-SEL-01, remplacer l'appel a CODE_VC_ID par
l'emission de la branche variable composite (LA lvl, chemin, X_disp).  Les constantes
ont un slot _disp comme les variables (la branche adresse `LVA ... _disp` de la meme
constante le prouve).

ORACLE :
  1. Reconstruction de TLALOC ; ADA_COMP.FINC identique a celui d'avant E-SEL (scalaires
     inchanges), TARGET_CODE.FINC : la seule difference avec E-SEL-01 est dans TRAITS
     (LA lvl, ... TRAITS_disp au lieu de LVA ..., et plus de La avant BLKMOV... verifier
     que le BLKMOV de CODE_RETURN a bien LI _TARGET_TRAITS.size, puis @data source).
  2. TARGET_CODE sur ADA_COMP et sur TARGET_CODE : plus de `placement STR incoherent`,
     binaires IDENTIQUES a ceux de la veille (oracle C0 point 3).
  3. Puis ARM64 + NULL_PROG -> `hors tranche arm64 : LINK` ; refus LEX sur codi discordant.
  4. Temoin SEL_CST (E-SEL-01, point 3) : X := P.K ; Y := P.K.B -- 3/4, 4.

PIEGE A CONSIGNER : forme du resultat des producteurs composites -- la selection par
paquetage (DN_SELECTED) laisse @data, le nom simple (DN_USED_OBJECT_ID) laisse @doublet ;
un remede qui emprunte le chemin de l'un pour la syntaxe de l'autre copie le doublet
au lieu des donnees, sans aucun message.

----------------------------------------------------------------------------------------------------
[E-SEL-02]  expander-expressions.adb  --  CODE_SELECTED : constante composite selectionnee laisse @data
----------------------------------------------------------------------------------------------------
ANCRE (texte existant, inchange) :
<<<
	    PUT_LINE( tab & "LI" & tab & PRINT_NUM( D( SM_VALUE, DESIGNATOR ) ) );
	  else
>>>
SUPPRIMER (juste apres l'ancre) :
<<<
			--| Piege n 1xx (temoin EMITS.TRAITS, 26/08) : PKG.CST d'un type
			--| COMPOSITE (record constant a agregat) n'a pas de SM_VALUE
			--| numerique -- PRINT_NUM plantait sur DN_VOID.  Le nom SIMPLE
			--| passait deja par CODE_VC_ID (LOAD_MEM) : meme chemin, meme
			--| resultat (@doublet), la selection par paquetage ne change
			--| pas l'objet.  Scalaires : LI inchange (octet-identite ADA_COMP).
	    CODE_VC_ID( DESIGNATOR_DEFN );
>>>
REMPLACER PAR :
<<<
			--| Piege n 1xx (temoin EMITS.TRAITS, 26/08) : PKG.CST d'un type
			--| COMPOSITE (record constant a agregat) n'a pas de SM_VALUE
			--| numerique -- PRINT_NUM plantait sur DN_VOID.  CONTRAT de la
			--| forme selectionnee (CODE_COMPOSITE_DATA_ADDRESS, regle unique
			--| n 112) : un DN_SELECTED composite laisse @DATA, pas @doublet --
			--| meme emission que PKG.VARIABLE composite ci-dessus (LA lvl,
			--| X_disp = data_ptr).  Un premier remede par CODE_VC_ID laissait
			--| @doublet : le BLKMOV appelant copiait le doublet lui-meme
			--| (TR.PROLOGUE_SIZE = octets d'info_ptr, placement STR incoherent
			--| P2B/P3 sur ADA_COMP).  Scalaires : LI inchange.
	    PUT( tab & "LA " & IMAGE( DI( CD_LEVEL, DESIGNATOR_DEFN ) ) & ", " );
	    REGIONS_PATH( DESIGNATOR_DEFN );
	    PUT_LINE( DESIGNATOR_STR & "_disp" );
>>>
MOTIF : contrat @data de la forme selectionnee (regle unique n 112) ; meme emission que PKG.VARIABLE composite.
(Les lignes `\t  end if;` puis `\telse -- contexte adresse` ... restent telles quelles.)
