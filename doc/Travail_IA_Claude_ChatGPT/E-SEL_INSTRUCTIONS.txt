========================================================================================================================
LOT E-SEL  --  expander : PKG.CONSTANTE composite (CODE_SELECTED, DN_CONSTANT_ID) -- debloque la compilation d'EMITS
========================================================================================================================

DIAGNOSTIC : `return X86_64_TARGET.TRAITS` -> CODE_RETURN record -> CODE_COMPOSITE_DATA_ADDRESS
-> CODE_EXP( DN_SELECTED ) -> CODE_SELECTED, designateur DN_CONSTANT_ID, IS_SOURCE : la
branche emet inconditionnellement `LI PRINT_NUM( SM_VALUE )`, c'est-a-dire suppose une
constante SCALAIRE STATIQUE.  Une constante record (agregat) n'a pas de SM_VALUE numerique
(DN_VOID) : PRINT_NUM leve PROGRAM_ERROR (idl.adb:538).  Le nom SIMPLE d'une telle constante
passe par CODE_USED_OBJECT_ID -> CODE_VC_ID -> LOAD_MEM et fonctionne : le trou n'est que
dans la forme selectionnee PAQUETAGE.CONSTANTE.

REMEDE : dans la branche DN_CONSTANT_ID / IS_SOURCE, discriminer sur le type de l'objet :
scalaire ou acces -> LI inchange ; composite -> CODE_VC_ID( DESIGNATOR_DEFN ), le chemin du
nom simple.  Une modification, un fichier.  (FULL_TYPE_VIEW et CODE_VC_ID sont deja visibles
dans EXPRESSIONS : CODE_VC_ID a sa spec dans expander.adb:248, FULL_TYPE_VIEW est employe
non qualifie ligne 7021.)

ORACLE :
  1. Reconstruction de TLALOC ; ADA_COMP.FINC produit par le nouvel expander cmp a celui
     de la veille : IDENTIQUE (aucun PKG.CST composite dans le corpus : il aurait plante).
  2. Compilation de target_code-emits.adb passe ; puis oracle du lot C0 (filet TC_TEST,
     ADA_COMP.x86exe identique, refus arm64 sur LINK, refus LEX sur codi discordant).
  3. Temoin de non-regression a ajouter au filet expander (SEL_CST) :
       package P is
         type R is record A, B : INTEGER; end record;
         K : constant R := ( A => 3, B => 4 );
       end P;
       ... X : P.R := P.K;  Y : INTEGER := P.K.B;  -- attendus 3/4, 4
     Son jumeau par nom simple (use P ; K) est le controle.

TROU VOISIN, CONSIGNE MAIS NON TRAITE ICI : PKG.CST d'un scalaire NON STATIQUE
(K : constant INTEGER := F( 1 )) suit toujours la branche LI et plantera de la meme
facon dans PRINT_NUM -- bruyant, donc acceptable en attendant ; le remede serait le
meme (CODE_VC_ID) sous la garde de staticite deja employee par CODE_CONVERSION et
CODE_QUALIFIED (SV.PT = HI and SV.NOTY = DN_NUM_VAL, or else SV.TY = DN_NUM_VAL).


----------------------------------------------------------------------------------------------------
[E-SEL-01]  expander-expressions.adb  --  CODE_SELECTED : constante composite selectionnee
----------------------------------------------------------------------------------------------------
ANCRE (texte existant, inchange) :
<<<
        elsif  DESIGNATOR_DEFN.TY = DN_CONSTANT_ID  then
>>>
SUPPRIMER (juste apres l'ancre) :
<<<
	if  IS_SOURCE  then
	  PUT_LINE( tab & "LI" & tab & PRINT_NUM( D( SM_VALUE, DESIGNATOR ) ) );
>>>
REMPLACER PAR :
<<<
	if  IS_SOURCE  then
	  if  FULL_TYPE_VIEW( D( SM_OBJ_TYPE, DESIGNATOR_DEFN ) ).TY in CLASS_SCALAR
	  or else  FULL_TYPE_VIEW( D( SM_OBJ_TYPE, DESIGNATOR_DEFN ) ).TY = DN_ACCESS
	  then
	    PUT_LINE( tab & "LI" & tab & PRINT_NUM( D( SM_VALUE, DESIGNATOR ) ) );
	  else
			--| Piege n 1xx (temoin EMITS.TRAITS, 26/08) : PKG.CST d'un type
			--| COMPOSITE (record constant a agregat) n'a pas de SM_VALUE
			--| numerique -- PRINT_NUM plantait sur DN_VOID.  Le nom SIMPLE
			--| passait deja par CODE_VC_ID (LOAD_MEM) : meme chemin, meme
			--| resultat (@doublet), la selection par paquetage ne change
			--| pas l'objet.  Scalaires : LI inchange (octet-identite ADA_COMP).
	    CODE_VC_ID( DESIGNATOR_DEFN );
	  end if;
>>>
MOTIF : la selection par paquetage ne change pas la nature de l'objet ; regle unique avec le nom simple.
(Les lignes `else -- contexte adresse` ... `end if;` qui suivent restent telles quelles.)
