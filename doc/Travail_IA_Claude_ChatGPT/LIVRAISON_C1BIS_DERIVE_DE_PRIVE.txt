DIAGNOSTIC DU CRASH conv_der1 (PROGRAM_ERROR, declarations.adb:1314)
--------------------------------------------------------------------------------

Le DIANA joint tranche.  `type DSET is new SETS.SET;` (dérivation d'un type
PRIVÉ, hors du paquetage) produit la SECONDE SAVEUR du nœud `private`, prévue
par la grammaire (diana_NODES : `sm_derived :TYPE_SPEC` en tête d'attributs) :

    SM_TYPE_SPEC(type_id DSET) = [DN_PRIVATE,P271,L4]
        SM_DERIVED   → [DN_PRIVATE,P257,L29]   (la vue du parent SETS.SET)
        SM_TYPE_SPEC → ABSENT (= VOID)         (aucune complétion ne viendra)

Or TOUT le perçage de vue de la maison suppose l'invariant « la chaîne
SM_TYPE_SPEC des privés termine sur la vue pleine » : FULL_TYPE_VIEW (utils),
FULL_VIEW et FULL_VIEW_LOCAL (expressions, clones de la même règle), plus une
vingtaine de boucles while locales.  Sur cette saveur, la chaîne rend VOID :
CODE_TYPE_DECL affiche un « skip PRIVATE (deferred to full type) » MENSONGER
(rien ne viendra), puis `DS : DSET` meurt dans CODE_VC_NAME sur DN_VOID —
c'est votre trace, et c'est la vérification structurelle qui fait son travail.

La réparation suit le précédent maison : ROOT_RECORD suit DÉJÀ SM_DERIVED
(n° 120b, expressions 1222).  On l'enseigne à la règle de perçage : quand
SM_TYPE_SPEC est VOID sur un privé, suivre SM_DERIVED — la vue pleine est
celle du PARENT, représentation identique (LRM 3.4, même doctrine que C1).
Aucun descripteur propre à élaborer : le FINC de DS doit devenir celui de S.

Discipline n° 114/115 respectée : CHAQUE modification ci-dessous est exercée
par conv_der1 —
  M1 par `DS : DSET` (CODE_VC_NAME → CODI.FULL_TYPE_VIEW) ;
  M2+M4 par `DSET( S )` et `SETS.SET( DS )` (CODE_CONVERSION → FULL_VIEW) ;
  M5 par `DS := DSET( S )` (CODE_ASSIGN, destination objet) ;
  M8 par `DS` en expression source (CODE_VC_ID) ;
  M6 par l'élaboration du bloc S2 (message DEBUG discriminé).
NON MODIFIÉ (rameau qui serait non exercé) : le clone FULL_VIEW_LOCAL et les
boucles while restantes — chacune rend VOID puis sonne bruyamment en aval si
un jour traversée avec cette saveur ; dette d'UNIFICATION du perçage (trois
copies de la règle + boucles locales → un seul point) consignée en M7d.
Voie architecturale alternative notée pour ce jour-là : ÉCRIRE la vue pleine
du parent dans SM_TYPE_SPEC du nœud dérivé-de-privé à sa déclaration (un
écrivain, tous les lecteurs inchangés) — praticable seulement si idl.ads
offre un setter d'attribut TREE, à vérifier chez vous.

MODIF M1 — expander-utils.adb, FULL_TYPE_VIEW (la règle)
--------------------------------------------------------------------------------
  ANCRE (unique, inchangée, 2 lignes au-dessus) :
  function		  FULL_TYPE_VIEW		( T : TREE )	return TREE

  BLOC À SUPPRIMER (unique, le corps de la boucle) :
    loop
      if R.TY = DN_PRIVATE or else R.TY = DN_L_PRIVATE then
        R := D( SM_TYPE_SPEC, R );

      elsif R.TY = DN_INCOMPLETE then
        R := D( XD_FULL_TYPE_SPEC, R );

      else
        return R;
      end if;
    end loop;

  BLOC DE REMPLACEMENT :
      if R.TY = DN_PRIVATE or else R.TY = DN_L_PRIVATE then
        if  D( SM_TYPE_SPEC, R ) /= TREE_VOID  then
          R := D( SM_TYPE_SPEC, R );

        elsif  D( SM_DERIVED, R ) /= TREE_VOID  then
			--| Seconde saveur DIANA de `private`/`l_private` (grammaire
			--| diana_NODES : SM_DERIVED en tete d'attributs) : type DERIVE
			--| d'un type prive, declare HORS du paquetage -- SM_TYPE_SPEC
			--| est VOID et aucune completion ne viendra.  La vue pleine est
			--| celle du PARENT : representation identique (LRM 3.4, meme
			--| doctrine que C1).  Precedent maison : ROOT_RECORD suit deja
			--| SM_DERIVED (n 120b).  Decouverte temoin CONV_DER1 30/07
			--| (ERREUR CODE_VC_NAME TYPE_SPEC.TY = DN_VOID sur DS : DSET).
          R := D( SM_DERIVED, R );

        else
          return R;								-- ni completion ni parent : anomalie, bruyante en aval
        end if;

      elsif R.TY = DN_INCOMPLETE then
        R := D( XD_FULL_TYPE_SPEC, R );

      else
        return R;
      end if;
