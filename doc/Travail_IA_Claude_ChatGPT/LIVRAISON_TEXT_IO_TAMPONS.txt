LIVRAISON TEXT_IO : TAMPONS D'ENTREE-SORTIE PAR FICHIER (30 aout 2026)
=======================================================================

Constat (strace -f -c, expander-expressions.adb W, apres page_man 16384) :
908 699 write et 275 747 read sans lseek, soit un syscall par PUT/PUT_LINE
(SYS_FILE_WRITE) et par caractere lu (SYS_FILE_READ de 1 octet). Tout le
trafic fichier de TEXT_IO passe par trois primitives : PUT_RAW (CHARACTER),
PUT_RAW (STRING) et GET_RAW ; c'est la qu'on tamponne. La console (ID = -1,
SYS_PUT_CHAR / SYS_PUT_STR / SYS_GET_CHAR / SYS_GET_STR) reste NON
tamponnee : messages de diagnostic et EXCEPTION NON RATTRAPEE inchanges.

Choix de conception :
- Le tampon n'est PAS dans FILE_TYPE (le record est copie : DEFAULT_OUTPUT
  := FILE, STD_OUTPUT...) ; il est indexe par le descripteur Linux (FILE.ID),
  dans une table du corps de paquetage. Pas de modification de text_io.ads.
- 32 descripteurs tamponnes (0 .. 31), 4096 octets chacun (128 Kio dans la
  VARzone de niveau 0). Un ID hors table prend l'ancien chemin (un syscall
  par appel) : comportement identique, seulement plus lent.
- Ecriture : vidage quand le tampon est plein, a CLOSE, a RESET, et lorsque
  qu'une chaine ne tient pas (les chaines > 4096 partent directement).
- Lecture : remplissage par blocs de 4096 ; fin de fichier quand read rend
  0 (ou < 0 : erreur assimilee a EOF, comme avant).
- CREATE/OPEN remettent le tampon de l'ID a zero (reutilisation d'un
  descripteur ferme), DELETE et RESET aussi.
- Une exception non rattrapee sort par SYS_EXIT sans CLOSE : le contenu du
  tampon de sortie (au plus 4 Kio par fichier) est perdu. Pour un FINC en
  cours, sans consequence (il est inutilisable) ; a garder en tete pour un
  fichier de trace : PUT_LINE sur la console n'est pas concerne.
- VARzone non zeroee (dette consignee) : les compteurs sont initialises
  explicitement dans la partie begin du corps de paquetage.

Un seul commit C-T1, neuf modifications, toutes dans text_io.adb. Ordre des
declarations Ada 83 respecte : les nouveaux types/objets sont inseres avant
le premier corps de sous-programme ; les nouveaux corps (WRITE_RAW,
READ_RAW, FLUSH_OUT, RESET_BUFFER) precedent leurs premiers usages (CLOSE).
ASCII pur, tabulations a preserver dans les blocs de remplacement.
Numeros de lignes donnes a titre indicatif (fichier recu, 4547 lignes).

REMPLACER PAR :
			-- Tampons d'entree-sortie par descripteur Linux (hors LRM).
			-- Indexes par FILE.ID et non loges dans FILE_TYPE, dont les
			-- valeurs sont copiees (DEFAULT_OUTPUT := FILE). Un ID hors
			-- table prend l'ancien chemin : un syscall par PUT_RAW/GET_RAW.

  BUF_SIZE		: constant	:= 4096;
  MAX_BUF_ID		: constant	:= 31;
  subtype BUF_LEN		is INTEGER range 0 .. BUF_SIZE;

  type IO_BUFFER		is record
			  DATA		: STRING( 1 .. BUF_SIZE );
			  OUT_LEN		: BUF_LEN;						-- DATA( 1 .. OUT_LEN ) en attente d'ecriture
			  IN_POS		: BUF_LEN;						-- octets deja consommes en lecture
			  IN_LEN		: BUF_LEN;						-- DATA( IN_POS+1 .. IN_LEN ) restent a lire
			end record;

  BUFS			: array( 0 .. MAX_BUF_ID ) of IO_BUFFER;


			---------
  procedure		WRITE_RAW		( ID :INTEGER; ITEM :STRING )				-- write( ID, ITEM ) direct, sans tampon
  is			---------

    ERR_CODE	: INTEGER;

		-----------------
    function	WRITE_SYSTEM_CALL		( FILE_ID :INTEGER; LENGTH :POSITIVE )		return INTEGER
    is		-----------------
    begin
      ASM_OP_2'( OPCODE => Ld, LVL => 2, OFS => -16 );							-- LENGTH en -16
      ASM_OP_2'( OPCODE => LIa, LVL => 1, OFS => -16 );							-- @CHARS sur parametre ITEM de WRITE_RAW
      ASM_OP_2'( OPCODE => Ld, LVL => 2, OFS => -8 );							-- ID
      ASM_OP_0'( OPCODE => SYS_FILE_WRITE );
      ASM_OP_2'( OPCODE => SD, LVL => 2, OFS => -24 );							-- Retour du resultat syscall

    end	WRITE_SYSTEM_CALL;
	-----------------
  begin
    if  ITEM'LENGTH = 0  then return; end if;
    ERR_CODE := WRITE_SYSTEM_CALL( ID, ITEM'LENGTH );

  end	WRITE_RAW;
	---------


			--------
  function		READ_RAW		( ID :INTEGER; ITEM :STRING )	return INTEGER		-- read( ID, ITEM ) direct, rend le nombre d'octets lus
  is			--------

		----------------
    function	READ_SYSTEM_CALL		( FILE_ID :INTEGER; LENGTH :POSITIVE )		return INTEGER
    is		----------------
    begin
      ASM_OP_2'( OPCODE => Ld, LVL => 2, OFS => -16 );							-- LENGTH en -16
      ASM_OP_2'( OPCODE => LIa, LVL => 1, OFS => -16 );							-- @CHARS sur parametre ITEM de READ_RAW
      ASM_OP_2'( OPCODE => Ld, LVL => 2, OFS => -8 );							-- ID
      ASM_OP_0'( OPCODE => SYS_FILE_READ );
      ASM_OP_2'( OPCODE => SD, LVL => 2, OFS => -24 );							-- Retour du nombre d'octets lus

    end	READ_SYSTEM_CALL;
	----------------
  begin
    return READ_SYSTEM_CALL( ID, ITEM'LENGTH );

  end	READ_RAW;
	--------


			---------
  procedure		FLUSH_OUT		( ID :INTEGER )						-- vide le tampon de sortie de l'ID
  is			---------
  begin
    if  ID < 0  or else  ID > MAX_BUF_ID  then return; end if;
    if  BUFS( ID ).OUT_LEN > 0  then
      WRITE_RAW( ID, BUFS( ID ).DATA( 1 .. BUFS( ID ).OUT_LEN ) );
      BUFS( ID ).OUT_LEN := 0;
    end if;

  end	FLUSH_OUT;
	---------


			------------
  procedure		RESET_BUFFER	( ID :INTEGER )						-- oublie tout (ouverture, fermeture, reset, delete)
  is			------------
  begin
    if  ID < 0  or else  ID > MAX_BUF_ID  then return; end if;
    BUFS( ID ).OUT_LEN := 0;
    BUFS( ID ).IN_POS  := 0;
    BUFS( ID ).IN_LEN  := 0;

  end	RESET_BUFFER;
	------------

------------------------------------------------------------------------
NOTES DE TRANSCRIPTION MACHINE_CODE
------------------------------------------------------------------------

WRITE_RAW et READ_RAW sont des copies conformes de WRITE_SYSTEM_CALL de
PUT_RAW (STRING) : niveau 1 = le sous-programme de paquetage (ID en -8,
descripteur ITEM en -16, d'ou LIa 1,-16 pour l'adresse des caracteres),
niveau 2 = la fonction imbriquee (FILE_ID -8, LENGTH -16, resultat -24).
La seule difference de READ_RAW est l'opcode SYS_FILE_READ, dont la
convention de pile (LENGTH, @BUFFER, FILE_ID ; resultat sur [rbp]) est
celle de SYS_FILE_WRITE (CONVENTIONS_ARCHITECTURE, table des syscalls).
Le parametre ITEM de READ_RAW est declare `in` : il est passe par
descripteur, le noyau ecrit dans les caracteres pointes -- meme regime que
FILE :in FILE_TYPE modifie dans GET_RAW.
