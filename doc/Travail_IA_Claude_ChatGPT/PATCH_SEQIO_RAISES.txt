PATCH n 7 : raises manquants dans SEQUENTIAL_IO (dette de bibliotheque)
Fichier a modifier : sequential_io.adb (source Ada de la bibliotheque)
Nature             : volet A = un remplacement dans OPEN ;
                     volet B = audit des voisins, meme motif.
========================================================================

DIAGNOSTIC
----------
OPEN echoue sans lever : "if ERR_OR_ID >= 0 then ... end if;" SANS else.
IS_OPENED reste FALSE, l'appelant continue, et c'est la garde de READ
qui leve STATUS_ERROR -- sans message, puisque le handler NAME_ERROR de
READ_PARSE_TABLES n'a jamais rien recu.  C'etait la cause de l'episode
"STATUS_ERROR muet" depuis le premier jour.  LRM 14.2.1(7) : OPEN d'un
fichier inexistant => NAME_ERROR.  Reference interne : TEXT_IO.OPEN /
CREATE ont leur "else raise" ; SEQUENTIAL_IO est reste en chantier.
Dette de bibliotheque rendue visible par la sentinelle (motif du piege
n 74), invisible chez la reference GNAT dont le parse.bin etait present.

------------------------------------------------------------------------
VOLET A -- OPEN
------------------------------------------------------------------------
ANCRE (texte EXISTANT, fin du corps d'OPEN) :

    ERR_OR_ID := OPEN_SYSTEM_CALL( NAME );
    if  ERR_OR_ID >= 0  then
      FILE.ID := ERR_OR_ID;
      FILE.NAME( 1 .. NAME'LENGTH ) := NAME;
      FILE.NAME_LEN := NAME'LENGTH;
      FILE.IS_OPENED := TRUE;
      FILE.MODE := MODE;
      FILE.AT_END_OF_FILE := FALSE;
    end if;
  end	OPEN;

REMPLACER PAR :

    ERR_OR_ID := OPEN_SYSTEM_CALL( NAME );
    if  ERR_OR_ID >= 0  then
      FILE.ID := ERR_OR_ID;
      FILE.NAME( 1 .. NAME'LENGTH ) := NAME;
      FILE.NAME_LEN := NAME'LENGTH;
      FILE.IS_OPENED := TRUE;
      FILE.MODE := MODE;
      FILE.AT_END_OF_FILE := FALSE;
    else
      raise NAME_ERROR;								-- LRM 14.2.1(7) : ouverture impossible
    end if;
  end	OPEN;

NOTE : ajouter aussi, par symetrie avec TEXT_IO et le LRM, la garde
d'entree si elle manque :
    if  FILE.IS_OPENED  then raise STATUS_ERROR; end if;			-- LRM 14.2.1(4)
(le source montre que READ l'a, OPEN de TEXT_IO l'a ; verifier OPEN et
CREATE de SEQUENTIAL_IO.)

------------------------------------------------------------------------
VOLET B -- AUDIT du meme motif dans le reste du package
------------------------------------------------------------------------
Verifier chaque branche echec de syscall :
  - CREATE : "else raise USE_ERROR;"  (LRM 14.2.1(6), comme TEXT_IO) ;
  - DELETE / RESET : echec => USE_ERROR ;
  - garde d'entree STATUS_ERROR sur OPEN/CREATE (fichier deja ouvert)
    et sur toutes les operations (deja en place pour READ/WRITE d'apres
    les FINC -- verifier CLOSE, RESET, MODE, NAME, FORM, END_OF_FILE).
Regle : AUCUN chemin d'echec de syscall ne retourne silencieusement.

------------------------------------------------------------------------
TEST TEMOIN (a figer dans ORACLES_TESTS)
------------------------------------------------------------------------
parse.bin absent  => sortie "parse.bin FILE MISSING" PUIS sentinelle
                     "EXCEPTION NON RATTRAPEE : PROGRAM_ERROR"
                     (le handler de READ_PARSE_TABLES fait les deux).
parse.bin present => plus aucun STATUS_ERROR ; l'END_ERROR restant
                     releve du dossier "layout parse.bin" (regeneration
                     au layout TLALOC) et du GRMR_disp nul (patch n 8).
