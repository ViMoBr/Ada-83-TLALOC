COMMIT 1 -- record : type-info local par composant tableau anonyme, independant de CD_COMPILED

  ORACLE :
    1. Recompiler la SPEC de LEX. Dans le FINC, la section _LINE_OF_SOURCE contient desormais :
         _BDY__type = '_BDY__type'
          namespace _BDY__type
         ... (bloc identique a l'ancien bloc " namespace _STRING" : _COMP_SIZ=8, _FST_1=1,
              _LST_1 <- STANDARD.LEX.MAX_STRING_disp, SIZ, virtual at 4, end namespace)
       et la ligne :
         USEINFO 0, BDY, 	La 0, _BDY__type.use__info
       Plus AUCUNE occurrence de STANDARD._STRING dans cette section.
    2. Recompiler le CORPS lex.adb. La section _LINE_OF_SOURCE de l'elab_spec du corps est
       IDENTIQUE (diff vide) a celle de la spec : le bloc _BDY__type n'est plus tronque.
    3. Non-regression composant NOMME : un record dont un composant est d'un type/sous-type
       tableau declare (type BUF is array(1..N)... ; B : BUF) garde le chemin REGIONS_PATH
       inchange (USEINFO ..., La <lvl>, <chemin>._BUF.use__info) -- FINC identique avant/apres.
    4. Runtime : sur un objet LINE_OF_SOURCE du corps, une indexation/tranche de .BDY lit ses
       bornes via le __u du champ -> descripteur CONTRAINT local (SIZ = 255*8, FST_1=1,
       LST_1=255), et non plus le patron non contraint SIZ=-1 de STANDARD._STRING.

  VIGILANCE (ne pas corriger ici) :
    - Ne PAS retirer le marquage CD_COMPILED en aval (PROCESS_CONSTRAINED_ARRAY_TYPE_SPEC) :
      il reste la garde d'unicite legitime des types NOMMES (cf. journal A21001A).
    - Deux composants partageant une declaration (A, B : STRING(1..10)) emettent chacun leur
      _<comp>__type : redondance sure et negligeable, conforme a l'option retenue au journal.
    - XD_SOURCE_NAME du sous-type anonyme de COMPOSANT designe le type de base (pas l'objet,
      contrairement au cas objet du piege n 99) : TYPE_INFO_STR rendrait "_STRING" pour ce
      noeud. Aucun consommateur actuel ne fabrique ce chemin pour un composant (C6 recalcule
      les bornes par SM_INDEX_SUBTYPE_S ; le runtime passe par le slot __u), mais tout futur
      site qui voudrait nommer ce bloc doit reprendre la convention _<comp>__type ci-dessous.

		--| Piege n 46 generalise aux COMPOSANTS (session 5 aout) : le noeud
		--| DN_CONSTRAINED_ARRAY anonyme revient CD_COMPILED=TRUE au compile du
		--| CORPS (rechargement DCL apres la spec) -> le bloc info imbrique
		--| sautait ; et le USEINFO retombait dans les DEUX unites sur
		--| STANDARD._<base> (patron NON contraint, SIZ=-1) via XD_SOURCE_NAME.
		--| Remede aligne sur COMPILE_ARRAY_VAR (journal A21001A) : descripteur
		--| LOCAL _<comp>__type des qu'il y a contrainte anonyme, INDEPENDANT de
		--| CD_COMPILED ; le USEINFO pointe le bloc local au niveau courant.
		--| Type/sous-type NOMME : chemin REGIONS_PATH inchange.
		declare
		  COMP_CONSTRAINT	: TREE	:= TREE_VOID;
		  USE_LOCAL_INFO	: BOOLEAN	:= FALSE;
		begin
		  if  COMP_TYPE_DEF /= TREE_VOID  and then  COMP_TYPE_DEF.TY = DN_SUBTYPE_INDICATION  then
		    COMP_CONSTRAINT := D( AS_CONSTRAINT, COMP_TYPE_DEF );
		  end if;

		  if  COMP_CONSTRAINT /= TREE_VOID  or else  not DB( CD_COMPILED, COMP_TYPE )  then
		    USE_LOCAL_INFO := TRUE;
		    PUT_LINE( LOCAL_INFO_STR & " = '" & LOCAL_INFO_STR & "'" );
		    PUT_LINE( " namespace " & LOCAL_INFO_STR );
		    PROCESS_CONSTRAINED_ARRAY_TYPE_SPEC( COMP_TYPE );
		  end if;

		  PUT( "USEINFO " & LVL_STR & ", " & COMP_ID_STR & ", " );
		  if  USE_LOCAL_INFO  then
		    PUT_LINE( tab & "La " & LVL_STR & ", " & LOCAL_INFO_STR & ".use__info" );
		  else
		    PUT( tab & "La " & IMAGE( DI( CD_LEVEL, COMP_TYPE ) ) & ", " );
		    REGIONS_PATH( D( XD_SOURCE_NAME, D( SM_TYPE_SPEC, COMP_TYPE_NAME ) ) );
		    PUT_LINE( COMP_TYPE_STR & ".use__info" );
		  end if;
		end;
