DIAGNOSTIC (etabli sur A54B02A.FINC, lignes 428-448)
----------------------------------------------------
Le test n'a AUCUN tableau : les 4 sites ce_raise_ sont des checks E-A
de gamme d'affectation. Premier site execute apres la banniere :

    I := IDENT_INT( 2 );    avec    I : STAT RANGE 1..IDENT_INT( 5 );

Le sous-type de I est ANONYME (contrainte portee par la declaration
d'objet). Son XD_SOURCE_NAME remonte au TYPE DE BASE : le check emis
charge

	Ld	0, STANDARD._INTEGER.FST      (puis .LST)

Deux anomalies COMPOSEES :
  1. Mauvaise cible : bornes du BASE au lieu de la contrainte anonyme
     -- controle semantiquement VIDE au mieux.
  2. Le bloc _INTEGER de STANDARD n'est jamais ELABORE (l'include de
     _STANDRD.FINC precede le LINK 0 ; pas de store executable vers
     FST/LST). Memoire fraiche = 0 -> FST=0, LST=0 -> le check evalue
     2 > 0 -> CONSTRAINT_ERROR, deterministe.

Le site voisin J := IDENT_INT(2) avec J : DYN (sous-type NOMME
dynamique) controle contre _DYN.FST/LST correctement elaborees (1 et
5, IDENT_INT appele a l'elaboration) : les sous-types nommes sont
SAINS -- le probleme est strictement le cas anonyme.

Remarque : cette emission date d'E-A ; la levee etant deterministe,
A54B02A n'avait vraisemblablement pas ete re-execute individuellement
au filet E-A. Sans consequence sur le diagnostic.

M3. PIEGES.md -- nouveau piege n 80 (bloc a coller)

- **n° 80 — Le sous-type anonyme remonte au type de base ; les bornes des
  prédéfinis de STANDARD ne sont pas élaborées** (fossile A54B02A, pilier
  checks E-A). Pour un objet à contrainte portée par sa déclaration
  (`I : STAT RANGE 1..IDENT_INT(5)`), le spec anonyme a pour
  XD_SOURCE_NAME celui du TYPE DE BASE : toute émission qui fabrique un
  nom de bloc de bornes depuis ce spec vise `_INTEGER` de STANDARD — dont
  les VAR FST/LST ne sont JAMAIS élaborées (l'include de _STANDRD.FINC
  précède le LINK 0) : lecture de zéros, CONSTRAINT_ERROR déterministe
  sur le check de gamme. Garde : élision quand
  XD_SOURCE_NAME(spec) = XD_SOURCE_NAME(base). Deux dettes distinctes en
  sortent : (a) les contraintes anonymes ne sont PAS contrôlées ;
  (b) les blocs de bornes des scalaires prédéfinis sont ILLISIBLES à
  l'exécution — DANGER pour tout futur consommateur : chemin
  GENERIC_FIRST_LAST avec actuel = INTEGER (chaîne PARENT__u), attributs
  non statiques, checks E-D. À solder AVANT le site générique d'E-D.
