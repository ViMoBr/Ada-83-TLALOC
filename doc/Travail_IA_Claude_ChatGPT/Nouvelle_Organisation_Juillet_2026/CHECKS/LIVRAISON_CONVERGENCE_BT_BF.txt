LIVRAISON CORRECTIVE -- NON-CONVERGENCE FASMG (A54B01A, A54B02A,
A35801E) : oscillation de taille des branchements conditionnels BT/BF
========================================================================

DIAGNOSTIC
----------
"could not generate code within the allowed number of passes" =
oscillation entre passes, pas d'erreur de LLIR. Mecanisme :

1. BT/BF choisissent rel8 (2 octets) ou rel32 (6 octets) selon
   `disp` de la passe precedente (`disp = lbl-$` calcule APRES
   l'emission -- idiome multi-passe assume).
2. Le dimensionnement de branchements SEUL est monotone (un
   branchement qui s'allonge ne peut qu'allonger les deplacements des
   autres) : il converge toujours. L'ingredient ANTI-monotone qui
   permet le cycle, ce sont les ALIGNEMENTS (align_b/w/d/q dans
   VAR/STR/blocs) : +2 octets de code peuvent faire tomber jusqu'a
   6 octets de padding -- des deplacements RECULENT quand le code
   grossit -- un branchement rebascule court -- le padding revient --
   cycle sans point fixe. (Si l'elision push/pop de votre build fasmg
   est effective et non pas seulement comptee, elle est un second
   oscillateur du meme type : elision <-> adjacence <-> labels.)
3. Le correctif n 81 n'a ete que le declencheur : quelques octets de
   plus dans REPORT.FINC ont pose des BT/BF de ces trois executables
   pile sur la frontiere +/-127. Le pilier checks avait deja
   multiplie les BT (2 par site de check) : la population de
   branchements proches de la frontiere a explose, la probabilite de
   tomber sur une configuration cyclique avec.

LE PRECEDENT MAISON TRANCHE LA SOLUTION : la branche rel8 de BRA est
DEJA COMMENTEE dans codi -- BRA a deja ete de-oscille en le forcant
rel32 (le « BRA 5 octets » de NOTE_MODELE_EXCEPTIONS_v3 en est la
trace). BT et BF recoivent le meme traitement.

CONFIRMATION PREALABLE (une commande, avant tout collage) :
    fasmg -p 1000 A54B02A.fas A54B02A.bin
  - Echec encore a 1000 passes -> oscillation vraie (attendu).
  - Convergence vers ~100-200 passes -> convergence lente seulement ;
    le correctif ci-dessous reste le bon (il la supprime aussi).

------------------------------------------------------------------------
M4. PIEGES.md -- complement (au choix : n 82 ou appendice du n 81)
------------------------------------------------------------------------

- **n° 82 — L'oscillation rel8/rel32 sous alignements** (non-convergence
  fasmg A54B01A/02A/A35801E, déclenchée par le correctif n° 81). Les
  macros de branchement qui re-décident leur taille à chaque passe sur
  le `disp` de la passe précédente convergent tant que le système est
  monotone ; les ALIGNEMENTS introduisent une dépendance anti-monotone
  (du code en plus peut faire tomber du padding) et ouvrent des cycles
  sans point fixe. Symptôme : « could not generate code within the
  allowed number of passes » sur quelques exécutables seulement, après
  une modification anodine. BRA avait déjà été forcé rel32 pour cette
  raison (branche rel8 commentée — la trace était dans codi) ; BT/BF
  ont suivi quand le pilier checks a multiplié leur population près de
  la frontière ±127. Règle : toute décision de taille inter-passes doit
  être MONOTONE (verrou qui ne fait que s'élargir) ou supprimée.
