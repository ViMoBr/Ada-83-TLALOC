LIVRAISON -- PIEGE n 83 : L'ELABORATION PRE-LINK PIETINE LA VARZONE
Symptome : CHK_PREDEF0 -- BOOLEAN'LAST = 1722420000 via le chemin
use-info, INTEGER et CHARACTER justes.
========================================================================

MECANISME
---------
Dans CREATE_FAS_MAIN_FILE, l'include de _STANDRD.FINC precede le
LINK 0. Le code d'elaboration de _STANDRD s'execute donc avec
RBP = FP(0) : sa pile d'evaluation ecrit en [RBP+8], [RBP+16]... --
les PREMIERES CASES DE LA VARZONE (virtual at 8). Tout ce qui est
stocke dans les ~2 premiers qwords avant le LINK est ecrase par les
poussees des elaborations suivantes.

Les trois mesures de CHK_PREDEF0 signent le mecanisme :
  _BOOLEAN.use__info (parmi les premieres VAR de _STANDRD) : stocke
  correctement puis PIETINE -> pointeur-debris -> LST = 1722420000 ;
  _INTEGER et _CHARACTER, plus profonds que la portee des poussees
  (~2 qwords) : intacts. Le contexte-sentinelle du pilier 11, s'il
  loge tot, est gueri sans le savoir : reinitialise APRES le LINK par
  le wrapper -- ce qui a masque le piege jusqu'ici.

Consequence latente supplementaire : BOOLEAN'IMAGE passe par le meme
use__info clobbe (doublet images a __u+16, contrat END_BLOC_DEF /
GET_ENUM_IMAGES) -- vraisemblablement casse aujourd'hui aussi, gueri
par le meme correctif. Le temoin M2 le verifie.


------------------------------------------------------------------------
M1. expander.adb -- CREATE_FAS_MAIN_FILE : LINK 0 AVANT _STANDRD
------------------------------------------------------------------------
ANCRE : les lignes existantes :

	PUT_LINE( "include '../../bin/ADA__LIB/_STANDRD.FINC'" );

	PUT_LINE( tab & "LINK" & tab & "0, loc_siz" );

REMPLACER PAR (l'ordre s'inverse, rien d'autre ne change) :

	PUT_LINE( tab & "LINK" & tab & "0, loc_siz" );						-- PIEGE n 83 : LINK 0 AVANT l'elaboration de
												-- _STANDRD -- sinon la pile d'evaluation
												-- pre-LINK (RBP = FP(0)) ecrase les premieres
												-- cases de la VARzone (_BOOLEAN.use__info :
												-- BOOLEAN'LAST = debris via use-info).
	PUT_LINE( "include '../../bin/ADA__LIB/_STANDRD.FINC'" );

SURETE : LINK 0 n'ecrit pas le display (garde "rien au lvl 0" de la
macro), il ne fait qu'avancer RBP de loc_siz -- constante d'assemblage
resolue en avant par fasmg, deja utilisee ainsi. L'init sentinelle du
pilier 11 reste apres l'include, inchangee. Aucun autre ordre ne bouge.

Regenerer le .fas des executables (relancer la production, le wrapper
est recree) -- les FINC eux-memes sont inchanges.


------------------------------------------------------------------------
M2. chk_predef0.adb -- une ligne de plus au temoin (BOOLEAN'IMAGE)
------------------------------------------------------------------------
AJOUTER avant le end :

   PUT_LINE ("CHK_PREDEF0 IMAGE     " & BOOLEAN'IMAGE (TRUE)
           & " " & BOOLEAN'IMAGE (FALSE));

ORACLE complet attendu :
  CHK_PREDEF0 INTEGER   FIRST =-2147483648 LAST = 2147483647
  CHK_PREDEF0 CHARACTER FIRST = 0 LAST = 127
  CHK_PREDEF0 BOOLEAN   FIRST = 0 LAST = 1
  CHK_PREDEF0 IMAGE     TRUE FALSE
$? = 0. Puis filet complet (le wrapper change pour TOUS les
executables : tout doit rester vert, et rien d'autre ne doit changer).


------------------------------------------------------------------------
M3. PIEGES.md -- n 83 (bloc a coller)
------------------------------------------------------------------------

- **n° 83 — La pile d'évaluation pré-LINK piétine la VARzone** (trouvé
  par CHK_PREDEF0 : BOOLEAN'LAST = débris via use-info, INTEGER et
  CHARACTER justes). L'élaboration de _STANDRD s'exécutait avant le
  LINK 0 : RBP = FP(0), les poussées d'évaluation écrivent sur les
  premières cases de la VARzone — tout store précoce (~2 premiers
  qwords) est écrasé par les élaborations suivantes. _BOOLEAN.use__info
  était dans la zone ; la sentinelle du pilier 11, réinitialisée après
  le LINK par le wrapper, était guérie sans le savoir — ce qui a masqué
  le piège. Correctif : LINK 0 AVANT l'include de _STANDRD. Leçons :
  (a) un invariant de machine à pile (« les poussées vont au-dessus des
  frames ») ne vaut que si le frame est ALLOUÉ ; (b) la signature
  « premiers éléments faux, suivants justes » désigne une zone de
  recouvrement, pas une donnée fausse ; (c) le témoin qui imprime les
  VALEURS (CHK_PREDEF0) a trouvé en trois lignes ce qu'aucun test de
  déroulement ne pouvait voir — même famille de leçon que le n° 81.
