A COLLER DANS PIEGES.md

88. **La fonction D cause mais ne leve pas : tout idiome
    `exception when others` autour de D/DI est inoperant.** Sur attribut
    absent, D imprime `!! ... PAS D ATTRIBUT ...` (le message atterrit en
    commentaire dans le FINC) et retourne sans exception — le handler ne
    s'arme jamais. Corollaire jumeau : **attributs presents dans la CLASSE
    DIANA ≠ attributs POSES** (`CD_LEVEL` d'un spec de formel generique :
    slot present, contenu non num_val → « N EST PAS UN ENTIER »). Regle :
    avant tout nouvel acces D/DI, verifier la classe dans diana_NODES ET
    prevoir le cas non pose ; ne jamais garder par exception. Suspect a
    auditer : l'idiome de REPRESENTED_RECORD_SIZE_BITS (represented_items
    ~l.114). Vecu : SM_SIZE sur DN_INTEGER (STANDRD), SM_REPRESENTATION
    sur DN_ENUMERATION, CD_LEVEL sur formel (a35502r). (sessions juillet)

89. **La clause 'SIZE d'un scalaire ne vit PAS dans un attribut du spec :
    c'est un item DN_LENGTH_ENUM_REP separe, place APRES le type decl** —
    la classe Integer/enumeration n'a pas de SM_SIZE. La sem la traitait
    et posait CD_IMPL_SIZE... **sur la base anonyme seulement, pas sur le
    spec nomme** — or les variables portent SM_OBJ_TYPE → spec nomme :
    la clause etait honoree ET invisible du generateur depuis toujours
    (cause racine du `for AC_BYTE'SIZE use 8` ignore). Correctif : la sem
    pose sur LES DEUX specs (double geste, miroir du double CD_LEVEL).
    Regle : la representation vit sur la base ; tout couple base/nomme
    doit etre pose en miroir. (session ~17 juillet)

90. **La taille par defaut d'un `type T is range L..R` est celle du
    PARENT PREDEFINI (RM 3.5.4), pas le minimal signe de la gamme** —
    S8 (-128..127) recoit 16 bits car derive de SHORT_INTEGER. Et la
    SM_RANGE de la base anonyme est celle du parent (FST -32768...), pas
    la gamme declaree : **toute decision de representation se prend sur
    la gamme du PREMIER SOUS-TYPE NOMME** (base → XD_SOURCE_NAME →
    SM_TYPE_SPEC → SM_RANGE). Aucun objet n'est du type de base, tout
    sous-type nommable est contraint dans la gamme du premier nomme : le
    conteneur ne recoit jamais d'autre valeur. (session ~16 juillet)

91. **Dans un corps generique PARTAGE, toute decision STATIQUE sur un
    formel est suspecte : l'information doit voyager par le cadre GFP**
    (modele __ld/__st ; la table F-4a n'est remplie que pendant la
    compilation d'une instanciation, pas du corps). Vecu : T'IMAGE sur
    formel discret (a35502r) — la resolution statique vers l'actuel eut
    soude le PREMIER actuel dans le corps partage. Remede dessine (non
    pose) : slot `__u` du contrat GFP (deja prevu au commentaire
    declarations ~1760 : `PRM: __u(8) __ld(16) __st(24)`) portant le
    use__info de l'actuel, 0 si actuel entier, dispatch a l'EXECUTION
    dans CODE_IMAGE (fichier correctif_v2_image_slot_u.txt).
    (session ~18 juillet)

92. **DN_ARRAY est le tableau NON contraint ; le contraint est
    DN_CONSTRAINED_ARRAY — et SM_COMP_TYPE vit sur la BASE du spec**
    (dispatch CODE_TYPE_DECL l.45 ; idiome l.555). Un test `TY =
    DN_ARRAY` sur un tableau contraint ne s'allume jamais. Vecu :
    STATIC_TYPE_ALIGN_BYTES rendait 8 pour tous les tableaux → layout
    identique a l'ancien (21332) apres reconstruction complete — le
    `return 8` conservateur en branche par defaut a borne le degat au
    sur-alignement (jamais de corruption). Regle : verifier le nommage
    DIANA dans le dispatch existant, pas le deviner. (session 19 juillet)

93. **Sites de load caches en litteral caractere : `'L' & SIZ_CHAR`
    echappe a un grep sur la chaine `"L"`.** Quatre sites hors inventaire
    du routage ULx, dont DEUX chargent les patrons FST/LST
    (CODE_SCALAR_SUBTYPE_FIRST_LAST, LOAD_BOUND du pilier CHECKS) : non
    routes, un Lb signe de LST=255 rend -1 et casse range checks et
    'FIRST/'LAST des le premier conteneur 8 bits. Regle d'inventaire :
    grepper `"L" &` ET `'L' &` (et de meme pour tout prefixe d'emission).
    (session ~15 juillet)

## Sessions ~13-19 juillet 2026 — Lot « tailles scalaires » : loads non
signes ULx, clauses 'SIZE effectives, alignement par composant ;
GRMR 26644 → 21328 ; parse.bin lu par le bootstrap

Point de depart : taille exacte de GRMR (tables LALR). L'examen du FINC
revele un record de 26 644 octets pour 21 326 utiles : AC_BYTE (0..255,
'SIZE use 8) traite en 16 bits — TLALOC prend tout en signe — et STATOFS
alignant sur la taille TOTALE du champ. Objectif fixe : honorer les
clauses et rejoindre le layout GNAT natif (compatibilite binaire des
fichiers parse.bin/diana.bin ecrits par les outils hotes).

**Chemin de load non signe (phases neutres).** 3 primitives FETCH_*_U +
6 enveloppes ULb/ULw/ULd, ULIb/ULIw/ULId (movzx BE→B6, BF→B7 ; pas de
movzx dword : mov 32 bits SANS REX zero-etend, un octet de moins que le
movsxd). Pas de ULq ni de stores non signes (troncature indifferente).
Predicat IS_UNSIGNED_TYPE dans UTILS : FST statique >= 0 du PREMIER
SOUS-TYPE NOMME (piege n° 90) ; enumeres par SM_REP des litteraux (aucun
negatif), jamais SM_REPRESENTATION (n'existe pas dans la classe, piege
n° 88). Routage par OPER_LOAD_STR/OPER_LOADI_STR : LOAD_MEM (variables,
parametres in, out/in-out relus — piege n° 80 —, renommages, generiques),
puis expressions/instructions/declarations, puis les 4 sites caches en
litteral caractere (piege n° 93). Neutralite prouvee a chaque lot :
conteneurs signes ⇒ bit haut jamais leve ⇒ movzx == movsx ; oracle =
filet vert + diff .finc reduit aux substitutions L→UL.

**Clauses 'SIZE : la sem etait la bonne autorite — et l'avait presque.**
Temoin TSIZ (6 types canaris + sous-type + enum + tableau) et dumps
post-sem/post-expander : la taille par defaut est celle du parent
predefini (S8 = 16, piege n° 90) ; la clause etait HONOREE par la sem
mais posee sur la base seule (piege n° 89) pendant que le generateur
lisait le spec nomme — clause invisible depuis toujours. Deux approches
expander successivement ecrites puis ABANDONNEES : CONTAINER_SIZE
(pas 4 : lecture SM_SIZE — attribut inexistant, D cause sans lever,
piege n° 88 ; puis ecrasait la valeur sem) et table SIZE_CLAUSE +
pre-passe DN_LENGTH_ENUM_REP (rendue inutile). Resolution finale par
SOUSTRACTION : une ligne de sem (poser sur les deux specs), suppression
du calcul cote expander, conservation du pas 2 (OPER_SIZ_CHAR resolu sur
la base — la piece qui rend la clause visible) et du pas 3 (copie
base→sous-type dans CODE_SUBTYPE_DECL). Sans clause, un 0..255 reste 16
(parent SHORT_INTEGER) : RM-conforme, assume ; le retrecissement par
defaut = amelioration sem future, avec l'INVARIANT : le jugement
« FST >= 0 du premier nomme » de la sem et celui d'IS_UNSIGNED_TYPE
doivent rester mot pour mot le meme.

**Alignement par composant.** STATOFS passe a 3 parametres (algn:0 =
compat ancienne regle) ; STATIC_TYPE_ALIGN_BYTES : scalaire → taille du
conteneur, tableau → recursion sur le composant (via la BASE et
DN_CONSTRAINED_ARRAY, piege n° 92 — premiere version fausse, layout
identique a l'ancien), record/access/defaut → 8 conservateur.
GRMR : 26 644 → 21 332 (clauses) → 21 328 (algn), 2 octets de padding
legitime devant NTER_LAST ; offsets = layout GNAT natif champ pour
champ. parse.bin (21 328, ecrit par l'outil LALR hote) LU par le
compilateur bootstrappe — SIZE_BYTES de SEQUENTIAL_IO vient du SIZ
runtime du patron — qui atteint desormais l'ouverture du source.
Reconstructions COMPLETES a chaque changement d'offsets (jamais
d'incremental a cheval).

**Reste ouvert** : (1) a35502r — T'IMAGE sur formel discret en corps
partage, slot __u dessine (piege n° 91, fichier correctif v2) ;
(2) unification STATIC_SIZE additif (21 326) / size=$ (21 328) — ecart
tombe de 6 a 2, toujours requis pour le stride des tableaux de records ;
(3) lot enumeres ('SIZE sur enum, >127 litteraux, MIN_REP negatif) ;
(4) garde de plausibilite du chargeur parse.bin (ST_TBL_LAST/AC_SYM_LAST/
AC_TBL_LAST en gamme, sinon message « layout incompatible ») ;
(5) audit de l'idiome exception de REPRESENTED_RECORD_SIZE_BITS.

- **Tailles scalaires** : clauses 'SIZE effectives (sem pose base+nomme ;
  expander lit par la base — pas 2/3). Sans clause, 0..255 = 16 bits
  (parent predefini, RM 3.5.4) : conforme, assume. Retrecissement par
  defaut = amelioration sem future ; invariant a preserver : meme
  jugement « FST statique >= 0 du premier sous-type nomme » que
  IS_UNSIGNED_TYPE.
- **Loads non signes** : ULb/ULw/ULd + ULIx routes partout (y compris
  patrons FST/LST). Enumeres : non signe ssi aucun SM_REP negatif.
- **STATOFS 3 parametres** (algn par composant) : compat algn:0 dans la
  macro pour FINC anciens. Layout record = GNAT natif (frontiere binaire
  parse.bin/diana.bin). Tout changement d'offsets ⇒ reconstruction
  bootstrap COMPLETE.
- **STATIC_SIZE additif ≠ size=$** (21 326 vs 21 328 sur GRMR) : ecart
  residuel = paddings d'alignement ; unification requise avant tout
  tableau de records statiques (stride via CD_IMPL_SIZE).
- **T'IMAGE sur formel generique** (a35502r) : NON RESOLU — corps
  partage, decision statique impossible ; remede dessine = slot __u du
  contrat GFP + dispatch runtime enum/entier (correctif_v2_image_slot_u).
  'VALUE/'WIDTH sur formel : meme motif, a auditer avec.
- **Chargeur parse.bin** : garde de plausibilite (*_LAST en gamme) a
  poser — transforme toute derive de layout en diagnostic d'une ligne.

### Tailles et representation des scalaires (juillet 2026)

**Partage des roles** : la SEM est l'autorite des tailles (CD_IMPL_SIZE
definitif : clause 'SIZE prioritaire, sinon taille du parent predefini),
posee EN MIROIR sur le spec nomme ET la base anonyme. L'EXPANDER ne
calcule aucune taille scalaire : il lit par la base (OPER_SIZ_CHAR),
propage aux sous-types (CODE_SUBTYPE_DECL), choisit le SIGNE des loads
(IS_UNSIGNED_TYPE : FST statique >= 0 du premier sous-type nomme ;
enumeres : aucun SM_REP negatif) et l'ALIGNEMENT des champs
(STATIC_TYPE_ALIGN_BYTES : conteneur du scalaire, recursion sur le
composant des tableaux via la base, 8 conservateur sinon).

**LLIR** : loads non signes ULb/ULw/ULd et ULIb/ULIw/ULId (zero
extension ; FETCH_BYTE_U/WORD_U = movzx, FETCH_DWORD_U = mov 32 bits
sans REX). Pas de ULq, pas de stores non signes. Le signe ne se joue
qu'au franchissement memoire→pile ; l'arithmetique 64 bits reste signee.

**STATOFS name, siz, algn** : algn = alignement du composant elementaire
en octets ; algn:0 = ancienne regle par taille totale (compatibilite).
Layout des records statiques = layout GNAT natif : c'est la convention
de la frontiere binaire (parse.bin, diana.bin) entre outils hotes et
monde TLALOC. Corollaire : tout changement de regle de layout impose une
reconstruction complete du bootstrap et une regeneration des fichiers
binaires — jamais de mixite de generations.
