Deux volets :

CE QUE LA FOUILLE A REVELE
--------------------------
Le chantier redoute s'effondre : les tables de litteraux EXISTENT DEJA.
La refonte BLOC_DEF du 9 juillet (LLIR_AJOUTS_3_6, pieges n 29 et 87,
gardien ENUM_TEST) fait emettre par CODE_ENUMERATION_DECL, pour CHAQUE
type enumere, un bloc IMAGES au format triplets (REP, LEN, caracteres...)
et le patron ENUM_USE_INFO etendu, layout CONTRACTUEL :

    SIZ@0 (dd) | FST@+4 | LST@+8 | pad | IMAGES.data_ptr@+16 | info_ptr@+24

TEXT_IO.ENUMERATION_IO consomme deja ce bloc (GET_ENUM_IMAGES, LIVa
__u+16) -- et sa boucle PUT contient l'algorithme de balayage a copier.
Deux consequences heureuses :

  1. {data_ptr, info_ptr} adjacents a use__info+16 forment DIRECTEMENT
     un doublet STRING : le code genere peut le passer tel quel en
     parametre, ZERO copie, zero nouvelle instruction LLIR.
  2. Contrairement a GET_ENUM_IMAGES (qui doit ruser en ASM_OP pour
     atteindre le patron via le GFP generique), ici le TYPE est connu
     STATIQUEMENT au site de l'attribut : l'appelant empile
     use__info+16 en trois instructions, et la primitive est de l'Ada
     PUR, calquee sur la boucle d'ENUMERATION_IO.PUT.

Il ne manquait donc que : la primitive (4A) et le dispatch (4B).

  function		ENUM_IMAGE	( REP :INTEGER; IMAGES :STRING )	return STRING
  is			----------
  -- Primitive Ada cachee de l''IMAGE des ENUMERES, pendant d'INTEGER_IMAGE.
  -- Appelee par le code genere : CODE_IMAGE empile le descripteur resultat,
  -- REP (l'argument de l'attribut, deja empile par l'appelant), puis le
  -- doublet IMAGES du type -- qui est le doublet contractuel pose par
  -- END_BLOC_DEF a use__info+16 (SIZ@0, FST@4, LST@8, pad, data_ptr@16,
  -- info_ptr@24 ; pieges n 29 et 87) : directement un doublet STRING,
  -- zero copie.  Format IMAGES : triplets ( REP, LEN, caracteres... ),
  -- le meme que celui parcouru par TEXT_IO.ENUMERATION_IO (PUT/GET).
    I		: POSITIVE	:= IMAGES'FIRST;
    ITEM_REP	: INTEGER;
    LEN		: INTEGER;
  begin
    while  I <= IMAGES'LAST  loop
      ITEM_REP := CHARACTER'POS( IMAGES( I ) );
      LEN      := CHARACTER'POS( IMAGES( I + 1 ) );

      if  ITEM_REP = REP  then
        declare
	-- Rebasage OBLIGATOIRE a 1..LEN (LRM 3.5.5 : la borne basse du
	-- resultat de 'IMAGE est 1) : LEX compte dessus (IMAGE(4..LGR)).
	-- Initialisation par tranche : c'est le patch n 3 de
	-- COMPILE_ARRAY_VAR qui rend cette declaration compilable.
          IMG	: constant STRING( 1 .. LEN )	:= IMAGES( I + 2 .. I + 1 + LEN );
        begin
          return IMG;
        end;
      end if;

      I := I + 2 + LEN;
    end loop;

    raise PROGRAM_ERROR;								-- valeur hors table : bruyant (piege n 53)

  end	ENUM_IMAGE;
	----------

REMPLACEMENT : remplacer cette SEULE ligne par le bloc ci-dessous.

      declare
        TS	: TREE	:= PREFIX_TYPE_SPEC;
      begin
      -- Depouiller les vues privees et remonter au type de BASE :
      -- 'IMAGE est un attribut du type de base (LRM 3.5.5).
        while  TS /= TREE_VOID
          and then  ( TS.TY = DN_PRIVATE  or else  TS.TY = DN_L_PRIVATE )  loop
          TS := D( SM_TYPE_SPEC, TS );
        end loop;
        while  TS /= TREE_VOID
          and then  D( SM_BASE_TYPE, TS ) /= TREE_VOID
          and then  D( SM_BASE_TYPE, TS ) /= TS  loop
          TS := D( SM_BASE_TYPE, TS );
        end loop;

        if      TS /= TREE_VOID
          and then  TS.TY = DN_ENUMERATION
          and then  D( XD_SOURCE_NAME, TS ) /= TREE_VOID
          and then  PRINT_NAME( D( LX_SYMREP, D( XD_SOURCE_NAME, TS ) ) ) /= "CHARACTER"
        then
        -- ENUMERE : primitive Ada cachee ENUM_IMAGE( REP, IMAGES ).
        -- REP est deja empile par l'appelant (convention fonction-tableau :
        -- descripteur resultat, puis parametres en ordre source) ; on
        -- empile IMAGES = use__info+16 du type de base, le doublet
        -- contractuel pose par END_BLOC_DEF (pieges n 29 et 87) --
        -- directement un doublet STRING, zero copie.
          declare
            TYPE_NAME	: TREE		:= D( XD_SOURCE_NAME, TS );
            TYPE_NAME_STR	:constant STRING	:= '_' & PRINT_NAME( D( LX_SYMREP, TYPE_NAME ) );
          begin
            PUT( tab & "La " & IMAGE( DI( CD_LEVEL, TS ) ) & ", " );
            CODI.REGIONS_PATH( TYPE_NAME );
            PUT_LINE( TYPE_NAME_STR & ".use__info" );
            PUT_LINE( tab & "LI" & tab & "16" );
            PUT_LINE( tab & "ADD" );
            PUT_LINE( tab & "CALL" & tab & "STANDARD. ,ENUM_IMAGE_L11" );
          end;

        else
        -- ENTIERS : comportement d'origine.  CHARACTER'IMAGE (guillemets,
        -- LRM 3.5.5) et prefixes non resolus : retombee BRUYANTE sur
        -- l'image de la position, comme avant (piege n 53).
          if  TS = TREE_VOID  or else  TS.TY /= DN_INTEGER  then
            PUT_LINE( "; CODE_IMAGE : prefixe non entier -- retombee image de position" );
          end if;
          PUT_LINE( tab & "CALL" & tab & "STANDARD. ,INTEGER_IMAGE_L11" );
        end if;
      end;

NOTES DE LECTURE
------------------------------------------------------------------------
1. SUFFIXE ENUM_IMAGE_L11 : PLACEHOLDER A VERIFIER.  Le "_L11" 
   d'INTEGER_IMAGE_L11 est le suffixe de decoration pose par sem/expander
   sur la primitive de _standrd, et il est ecrit EN DUR dans CODE_IMAGE.
   Apres regeneration de _STANDRD.FINC, relever le nom decore reel de
   ENUM_IMAGE (grep "ENUM_IMAGE" dans le FINC) et ajuster la chaine dans
   4B si ce n'est pas "_L11".  Meme rituel que pour INTEGER_IMAGE en son
   temps.

2. Contrat d'appel : CODE_IMAGE est atteint via CODE_FUNCTION_CALL
   (l'attribut-fonction), qui a DEJA empile le descripteur resultat
   (ANON_l_c fabrique la, cf. ANON_671_35 dans LEX.FINC) et l'argument
   REP (Lb du prefixe).  4B n'ajoute ENTRE l'argument et le CALL que les
   trois instructions du parametre IMAGES -- l'equivalent d'un appel Ada
   ENUM_IMAGE( REP, IMAGES ) en ordre source.

3. DEPENDANCE au patch n 3 : dans 4A, "IMG : constant STRING(1..LEN) :=
   IMAGES( I+2 .. I+1+LEN )" est une variable tableau initialisee par
   TRANCHE -- exactement le cas rendu compilable par le patch n 3.  Le
   rebasage 1..LEN est indispensable (LRM 3.5.5) : sans lui, LEX
   planterait sur IMAGE( 4 .. IMAGE'LENGTH ) puisque la tranche brute
   garde ses bornes d'origine.  Le glissement (memes longueurs, bornes
   differentes) est assure par la copie BLKMOV octets du patch n 3.

4. REP vs POS : la table IMAGES est cle-e par l'octet REP emis par
   CODE_ENUMERATION_DECL, et ENUMERATION_IO la compare a ENUM'POS --
   coherent tant que representation = position (pas de clause de
   representation d'enumere, hors sous-ensemble actuel).  4B passe le
   REP stocke (Lb), meme convention.

5. CHARACTER'IMAGE reste hors perimetre (guillemets requis par le LRM) :
   retombee bruyante sur l'image de position, comportement inchange.
   Idem pour tout prefixe non resolu -- commentaire FINC + chemin
   historique, jamais de silence.

6. Verification faite ici : syntaxe GNAT propre sur les deux fichiers
   patches (pour _standrd.adb, en neutralisant le nom de package
   "_standrd" que GNAT refuse -- liberte TLALOC assumee, hors patch).
   Visibilite : PREFIX_TYPE_SPEC est locale a CODE_ATTRIBUTE (declaree
   avant CODE_IMAGE), REGIONS_PATH/PRINT_NAME/DI/D deja employes dans
   le fichier ; l'idiome "La CD_LEVEL, REGIONS_PATH + _TYPE.use__info"
   est copie du fix SELARG (expander-instructions ~620).

7. TEMOINS.  (a) Etendre ENUM_TEST (gardien du contrat BLOC_DEF) d'un
   aller-retour 'IMAGE : COULEUR'IMAGE(VERT) = "VERT", y compris sur un
   type local de procedure (niveau > 0).  (b) Oracle bootstrap :
   LEX_IMAGE( LT_ABORT ) = "ABORT", puis la chaine complete
   GRMR_OP_IMAGE( GRMR_OP_VALUE( "nil" ) ) = "nil".  (c) Relancer
   ADA_COMP sur dis_bonjour : le CONSTRAINT_ERROR de HASH_POS doit
   disparaitre -- TXT recevra "LT_xxx" long de 6+, TRONQ ses vraies
   donnees (patch n 3), et la table des mots reserves son contenu.

8. Cout : aucun -- les blocs IMAGES sont deja dans chaque binaire
   depuis la refonte du 9 juillet ; 4A+4B ne font qu'y brancher enfin
   un deuxieme consommateur, statique celui-la.
