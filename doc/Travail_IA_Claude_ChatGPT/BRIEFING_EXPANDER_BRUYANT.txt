1. LE SIGNAL MAISON : UN POINT D'ENTREE UNIQUE
------------------------------------------------------------------------
Plutôt que N copies de message+raise, une procédure centrale, par ex. :

  procedure TROU( SITE :STRING; NOEUD :TREE );
    -- écrit "; !! TROU <SITE> : <NODE_NAME(TY)> <srcpos si dispo>"
    --   DANS LE FINC (traçabilité)  ET  SUR LA SORTIE D'ERREUR
    --   (la leçon du n° 96 : un commentaire FINC n'est vu par personne)
    -- puis raise PROGRAM_ERROR   (mode STRICT, défaut)

Variante utile : un mode RECENSEMENT (drapeau CODI ou variable d'env)
qui logge sans lever — un run d'expansion complet en mode recensement
donne d'un coup la liste des trous réellement traversés par le corpus,
donc l'ordre de priorité des implémentations. Puis retour au STRICT.

Bénéfices annexes : `grep TROU` = inventaire vivant ; le site est nommé
en clair ; la discipline devient mécanique pour tout futur ajout.

2. TAXONOMIE DES TROUS (tirée des deux segfaults de la session)
------------------------------------------------------------------------
A. CORPS `null;` COMPLETS de procédures CODE_* — le cas CODE_TYPE_
   MEMBERSHIP. Les pires quand ils sont en contexte d'EXPRESSION
   (contrat : empiler exactement une valeur — un trou = déséquilibre
   de pile à retardement).
B. BRANCHES MUETTES DE DISPATCHERS : `when others => null;`, ou
   elsif-chaînes SANS else final (le nœud inconnu tombe au travers).
   Les chaînes sans else ne se grep-ent pas : audit manuel de chaque
   dispatcher requis.
C. DEMI-BRUYANTS : PUT_LINE "; ... pas gere" SANS raise (~63 sites au
   comptage grep "a faire|pas gere|non fait|non gere"). Le message part
   dans le FINC, l'expansion continue, le code émis est faux/absent.
   Ex. : CODE_CONVERSION « cible non faite » (expressions ~6020).
D. VALEURS PAR DEFAUT MENSONGERES : fonctions qui répondent une valeur
   plausible au lieu de signaler. Ex. repéré : types_decls ~1392
   `when others => return 8;` — très probablement le
   STATIC_TYPE_ALIGN_BYTES du piège n° 117 (alignement 8 imposé aux
   records représentés). Catégorie la plus sournoise : jamais de crash,
   du layout faux.
E. LEGITIMES A ANNOTER : les `null;` VOULUS doivent le dire, sinon
   chaque futur audit les re-suspecte. Annotation proposée :
   `null;  -- INTENTIONNEL : <raison>`. Candidats vus : CODE_NULL_STM
   (le null Ada !), CODE_STM_PRAGMA (partiellement — certains pragmas
   comptent), 'BASE et conversions identité, "adresse déjà en pile"
   (expressions ~1227), fixed/float hors périmètre checks.

3. INVENTAIRE PRELIMINAIRE (sources du 27/07)
------------------------------------------------------------------------
Comptes bruts de `null;` : declarations 14, expressions 16,
instructions 15, expander.adb 9, structures 1, types_decls 1.

Corps entièrement vides identifiés dans expander-instructions.adb —
famille TASKING + divers (lignes approx.) :
  CODE_STM_PRAGMA (48)        -> légitime partiel, à annoter/trier
  CODE_NULL_STM (180)         -> INTENTIONNEL, à annoter
  CODE_ACCEPT (188)           -> TROU (tasking)
  CODE_TERMINATE (196)        -> TROU (tasking)
  CODE_ABORT (204)            -> TROU (tasking)
  CODE_SELECT_ALTERNATIVE (245) -> TROU (tasking)
  CODE_SELECTIVE_WAIT (297)   -> TROU (tasking)
  CODE_COND_ENTRY (512)       -> TROU (tasking)
  CODE_TIMED_ENTRY (520)      -> TROU (tasking)
  CODE_ENTRY_CALL (625)       -> TROU (tasking)
Le tasking est peut-être hors périmètre du bootstrap : raison de PLUS
d'être bruyant — un accept ignoré en silence est indéboguable.

CODE_ATTRIBUTE (expressions ~2760-2902) — CONTEXTE D'EXPRESSION,
priorité maximale, mêmes conséquences que le membership :
  'BASE -> null (identité : probablement légitime, annoter)
  'CALLABLE, 'COUNT, 'TERMINATED -> null (tasking, TROU)
  'LAST_BIT, 'POSITION, 'STORAGE[_SIZE?] -> null (rep-clauses, TROU)
  'RANGE -> null (TROU ou géré ailleurs : vérifier)
  'VALUE -> null (TROU — attribut courant !)
  when others => null  -> TROU générique : tout attribut non reconnu
                          est avalé. A transformer en TROU() d'abord.

Dispatchers `when others` à trier un par un (20 sites grep-és) :
certains lèvent déjà (structures:60 raise PROGRAM_ERROR — le modèle),
d'autres impriment sans lever (expressions:361 « pas gere ! »),
d'autres avalent (expressions:2902), d'autres mentent
(types_decls:1392 return 8 ; represented_items:135 SIZE_BITS := 0).

4. METHODE DE PARCOURS (ordre par risque)
------------------------------------------------------------------------
1) PRODUCTEURS D'EXPRESSIONS (contrat : +1 en pile) : arbre d'appel de
   CODE_EXP — dispatch, CODE_ATTRIBUTE, memberships, conversions,
   agrégats, used_ids. Tout trou = n° 115.
2) EMETTEURS D'ACTUELS ET DE RETOURS (contrats de frontière n° 112) :
   CODE_PROCEDURE_CALL, CODE_FUNCTION_CALL, CODE_RETURN.
3) INSTRUCTIONS (contrat : effet net nul en pile) : dispatch de
   CODE_INSTRUCTION, boucles, exits, raise, tasking.
4) DECLARATIONS/ELABORATION (contrat : VAR + init complets) :
   CODE_VC_NAME, renamings, types, génériques.
5) FONCTIONS DE LAYOUT (catégorie D) : tailles, alignements, offsets —
   croiser avec le chantier n° 117 (miroir n° 110 obligatoire).
Pour CHAQUE site : classer TROU() / INTENTIONNEL annoté / défaut
documenté. Zéro site sans verdict écrit.

Greps de départ :
  grep -n "null;" expander*.adb
  grep -n "when others" expander*.adb
  grep -n -i "a faire\|pas gere\|non fait\|non gere" expander*.adb
  + audit manuel des elsif sans else dans chaque dispatcher (non
    grep-able), en partant des dispatch de CODE_EXP / CODE_INSTRUCTION
    / CODE_DECL / CODE_OBJECT_ADDRESS / LOAD_MEM.

5. GARDE-FOUS COMPLEMENTAIRES (ceintures ET bretelles)
------------------------------------------------------------------------
- Empreintes FINC post-expansion (n° 116) : « ; debut if » suivi d'un
  BF nu ; DUP en tête de squelette or else. Un script de vérification
  des FINC produits, lancé après chaque expansion, attrape ce que le
  parcours aurait raté.
- Assert runtime en mode debug : rbp == FP(lvl)+alloc en tête des
  grandes boucles de phase — prend tout déséquilibre résiduel au tour
  où il naît.
- Oracle par trou comblé : chaque TROU() promu en implémentation reçoit
  son oracle (méthodologie ORACLES_TESTS), jamais d'implémentation sans
  rameau exercé (leçon des n° 114/115 : rameau jamais exécuté = faux).

6. DEFINITION DE FINI
------------------------------------------------------------------------
- grep "null;" expander*.adb ne rend QUE des lignes annotées
  INTENTIONNEL.
- grep "when others" ne rend que des raise, des TROU(), ou des cas
  documentés.
- Les 63 demi-bruyants sont promus TROU() ou implémentés.
- Un run d'expansion du corpus en mode RECENSEMENT rend la liste des
  trous vivants, consignée dans ETAT_PILIERS comme carnet de dettes.
- Entrée PIEGES : « la discipline TROU() » avec le n° 115 en fossile
  fondateur.
