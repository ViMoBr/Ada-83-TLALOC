desassemble (capstone) et chaque branchement interne verifie sur sa cible. Les commentaires des
DD sont ceux du codi. Les deux macros parametrees (BLK_OP_OCTET x3, LEXCMP siz/sgn) sont ecrites
a la main avec les deplacements pre-calcules et verifies (cbz +9 / cbnz -7 ; +11 +10 +11 -10 +6 +7
+6 +4 -3 +2).

PRINCIPES :
  - SIZE_OF = 4 x mots, tailles fixes : sauf LEXCMP (124 quelle que soit la paire de charges,
    FAULT hors 1/2/4/8 = err du codi) ; CVTXI = 192 ; BLK_OP = 60.
  - E_SDIV128 : les 29 mots de SDIV128_64_POS quittent CVTIX (C3) pour une brique partagee avec
    CVTXI - octets identiques (TC-ARM16 le garde).
  - Les temoins TC-ARM16 / TC-ARM21 sont le TEXTE de TC_TEST16 / TC_TEST21 (include codi_arm64,
    identifiants renommes kA16_n, kA21_n, BLAA21_disp, TA21NM...), memes verdicts : les 28 + 33
    etapes discriminantes par code de sortie, sur le Pi.

ORACLE (dans cet ordre) :
  1. Compilation ; pilote X86_64 nom vide : filet x86 vert, PASSE arm04..arm09, arm16, arm21.
  2. Laptop : fasmg + cmp sur TC_ARM16.FAS et TC_ARM21.FAS (et re-cmp de TC_ARM07/09 : E_SDIV128).
  3. Pi : ./TC_ARM16.BIN -> 0 ; ./TC_ARM21.BIN -> 0 (cree et supprime t21.tmp).
  4. ADA_COMP.x86exe inchange.
  5. Corpus : DIS_BONJOUR.arm64fas puis ADA_COMP.arm64fas -> cmp au binaire fasmg, identiques ;
     ADA_COMP.arm64exe sur le Pi compile NULL_PROG (la boucle de bootstrap arm est fermee
     quand TARGET_CODE.arm64exe assemble a son tour, sur le Pi, un binaire identique).
