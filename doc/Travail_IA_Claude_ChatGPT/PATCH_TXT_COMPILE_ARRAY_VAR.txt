RAPPEL DU DIAGNOSTIC
--------------------
Le FINC de GRMR_OPS montre, a l'elaboration de TXT (ligne 812) :

	; COMPILE_ARRAY_VAR ASSOC.TY non gere DN_SELECTED

L'initialiseur DN_SELECTED tombe dans la branche "non gere" du bloc
INITIALIZE : ni COVAR_ALLOCATE, ni copie.  TXT_disp reste un qword non
initialise, et la premiere indexation TXT(LL) de la boucle qui suit le
dereference -> segfault dans GRMR_OP_IMAGE.  C'est le frere du trou de
HASH_SEARCH (patch n 1) : un composant tableau inline n'a pas de doublet
{_disp,__u} propre.  Remede : allouer la destination (COVAR_ALLOCATE)
puis BLKMOV depuis l'@data du composant, obtenue par CODE_OBJECT_ADDRESS.
Attention, contrairement au repli defensif de la branche DN_QUALIFIED
(qui recoit un @doublet de CODE_EXP et extrait le data_ptr par "La ,0"),
CODE_OBJECT_ADDRESS livre DIRECTEMENT l'@data : pas de "La ,0" ici.

NOTES DE LECTURE
------------------------------------------------------------------------
1. Convention BLKMOV : la pile porte @DST, LEN(octets), @SRC -- meme
   ordre que le repli defensif DN_QUALIFIED et que le BLKMOV du site
   d'agregat de STASH (LVA ,HN / LI 17 / LVA A_17_disp / La ,0 / BLKMOV).

2. LEN est pris cote DESTINATION (SIZ du type de TXT, soit 17*8 bits / 8
   = 17 octets), comme dans le repli DN_QUALIFIED existant.  Le check de
   contrainte LRM 5.2.1 (longueurs egales) n'est pas emis, au meme
   niveau de rigueur que ce repli ; ici les deux cotes sont STRING(1..17).

3. La garde "designator /= DN_FUNCTION_ID" ecarte le cas P.F (appel de
   fonction sans parametre ecrit en nom selectionne), dont la convention
   de retour est un @descripteur et non une @data : il retombe dans la
   branche bruyante, exactement comme avant le patch (pas de regression,
   pas de retombee silencieusement fausse -- piege n 53).

4. Visibilite : CODE_OBJECT_ADDRESS est declare dans le spec interne
   d'EXPRESSIONS (expander.adb ligne 154) ; le sous-unite declarations
   appelle deja EXPRESSIONS.CODE_EXP / CODE_AGGREGATE / CODE_STRING_LITERAL,
   et DN_SELECTED / DN_INDEXED / AS_DESIGNATOR / DN_FUNCTION_ID y sont
   deja employes.  Aucun with/renames a ajouter.

5. FINC attendu au site de TXT apres recompilation : a la place du
   commentaire "; COMPILE_ARRAY_VAR ASSOC.TY non gere DN_SELECTED",
   on doit voir :
	Ld 1, _TXT__type.SIZ / LI 8 / DIV / CO_VAR / Sa 1, TXT_disp   (COVAR_ALLOCATE)
	La 1, TXT_disp                                                (@DST)
	Ld 1, _TXT__type.SIZ / LI 8 / DIV                             (LEN = 17)
	La 0, ITABLE_disp ... (indexation ITABLE(GO), checks) ... Lw  (valeur ITABLE)
	La 0, HTABLE_disp ... (indexation HTABLE, checks, offset) ... ADD
	LVA , STANDARD.GRMR_OPS._HTABLE_TYPE.HN                       (@SRC)
	BLKMOV
   La boucle TXT(LL) qui suit lit alors de vraies donnees, et le
   RETURN TXT(1..LL) (slice ANON_69_12) aussi.

6. Interaction avec le patch n 1 : independants (fichiers et chemins
   distincts), mais les DEUX sont necessaires pour que GRMR_OPS passe --
   HASH_SEARCH crashe ligne 651 sans le n 1, GRMR_OP_IMAGE crashe sur
   TXT_disp sans le n 2.  L'oracle TEST_HASH_GRMR peut couvrir les deux :
   GRMR_OP_VALUE exerce le n 1, GRMR_OP_IMAGE le n 2 (aller-retour
   GRMR_OP_IMAGE( GRMR_OP_VALUE("nil") ) = "nil").
